# 21 — I2C通信：软件I2C读写MPU6050

> 说明：本节对应江协科技《STM32入门教程-2023版》的 **[10-3] 软件I2C读写MPU6050**。由于无法直接取得视频的完整字幕与逐帧代码，本文根据可访问的分集信息、课程上下文、公开课程笔记以及器件资料整理；“核心代码”标记为标准外设库风格的参考实现，并保持与本节实验思路一致。

## 实验概述

本实验基于 STM32F103C8T6 标准外设库，不使用 STM32 内部的硬件 I2C 外设，而是通过普通 GPIO 手动模拟 I2C 时序，完成 MPU6050 六轴惯性传感器的寄存器读写。

实验主要实现以下功能：

1. 使用 PB10 模拟 SCL 时钟线，使用 PB11 模拟 SDA 数据线。
2. 编写软件 I2C 的 6 个基本时序单元：
   - 起始条件
   - 终止条件
   - 发送一个字节
   - 接收一个字节
   - 发送应答
   - 接收应答
3. 封装 MPU6050 的指定寄存器写入和指定寄存器读取函数。
4. 配置 MPU6050 的电源、采样率、数字低通滤波器、陀螺仪量程和加速度计量程。
5. 读取 `WHO_AM_I` 芯片 ID。
6. 连续读取三轴加速度和三轴角速度原始数据，并通过 OLED 显示。

本节的核心目标是理解分层驱动思想：

```text
应用层 main.c
        ↓
器件驱动层 MPU6050.c
        ↓
通信协议层 MyI2C.c
        ↓
GPIO 引脚与物理总线
```

## 硬件连接

本实验常见接线如下，具体仍应以开发板和 MPU6050 模块原理图为准。

| 器件/信号 | STM32F103C8T6 引脚 | 说明 |
|---|---:|---|
| MPU6050 VCC | 3.3V | 建议使用 3.3V 供电，避免不同模块电源设计带来的风险 |
| MPU6050 GND | GND | STM32 与传感器必须共地 |
| MPU6050 SCL | PB10 | 软件 I2C 时钟线，可根据代码修改为其他 GPIO |
| MPU6050 SDA | PB11 | 软件 I2C 双向数据线，可根据代码修改为其他 GPIO |
| MPU6050 AD0 | GND 或悬空 | 低电平时 7 位从机地址为 `0x68` |
| MPU6050 INT | 不接 | 本节采用轮询读取，不使用数据就绪中断 |
| MPU6050 XCL/XDA | 不接 | 辅助 I2C 接口，本节不使用 |
| OLED | 按已有 OLED 工程连接 | 用于显示芯片 ID 和六轴原始数据 |
| ST-Link V2 | PA13、PA14、GND、3.3V | SWD 下载与调试 |

> I2C 的 SCL 和 SDA 都需要上拉电阻。常见 GY-521 模块已经集成上拉电阻，因此通常不需要重复外接；若使用裸芯片或无上拉模块，则必须外接合适的上拉电阻。

### 2. MyI2C.c

```c
#include "stm32f10x.h"                                             // 引入芯片寄存器、GPIO 结构体和标准外设库函数声明
#include "MyI2C.h"                                                 // 引入本模块对外公开的软件 I2C 函数声明
#define MyI2C_W_SCL(x) GPIO_WriteBit(GPIOB, GPIO_Pin_10, (BitAction)(x)) // 定义写 SCL 宏，通过 PB10 输出指定逻辑电平
#define MyI2C_W_SDA(x) GPIO_WriteBit(GPIOB, GPIO_Pin_11, (BitAction)(x)) // 定义写 SDA 宏，通过 PB11 拉低或释放数据线
#define MyI2C_R_SDA() GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_11)    // 定义读 SDA 宏，从 PB11 的输入数据寄存器读取总线电平
void MyI2C_Init(void)                                              // 定义软件 I2C 初始化函数
{                                                                  // 进入软件 I2C 初始化函数体
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);          // 开启 GPIOB 外设时钟，使 PB10 和 PB11 的配置寄存器可以工作
    GPIO_InitTypeDef GPIO_InitStructure;                           // 定义 GPIO 初始化结构体，用于集中设置引脚模式和速度
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;               // 配置为开漏输出，使器件只能主动拉低并通过上拉电阻获得高电平
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;       // 同时选择 PB10 和 PB11，分别作为软件 I2C 的 SCL 与 SDA
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;              // 设置 GPIO 最大翻转速度，实际总线频率由软件时序决定
    GPIO_Init(GPIOB, &GPIO_InitStructure);                         // 将上述配置写入 GPIOB 控制寄存器并完成引脚初始化
    MyI2C_W_SCL(1);                                                // 将 SCL 写 1，在开漏模式下表示释放时钟线并由上拉电阻拉高
    MyI2C_W_SDA(1);                                                // 将 SDA 写 1，在开漏模式下表示释放数据线并让总线进入空闲状态
}                                                                  // 结束软件 I2C 初始化函数
void MyI2C_Start(void)                                             // 定义 I2C 起始条件生成函数
{                                                                  // 进入起始条件函数体
    MyI2C_W_SDA(1);                                                // 先释放 SDA，确保开始前数据线处于高电平
    MyI2C_W_SCL(1);                                                // 再释放 SCL，保证在时钟高电平期间改变 SDA
    MyI2C_W_SDA(0);                                                // 在 SCL 为高电平时将 SDA 从高拉低，形成标准起始条件
    MyI2C_W_SCL(0);                                                // 将 SCL 拉低，进入后续数据发送阶段并锁定 SDA 变化窗口
}                                                                  // 结束 I2C 起始条件函数
void MyI2C_Stop(void)                                              // 定义 I2C 终止条件生成函数
{                                                                  // 进入终止条件函数体
    MyI2C_W_SDA(0);                                                // 先将 SDA 拉低，为产生低到高跳变做好准备
    MyI2C_W_SCL(1);                                                // 释放 SCL，使时钟线回到高电平
    MyI2C_W_SDA(1);                                                // 在 SCL 为高电平时释放 SDA，形成标准终止条件
}                                                                  // 结束 I2C 终止条件函数
void MyI2C_SendByte(uint8_t Byte)                                  // 定义发送一个字节函数，参数 Byte 为待发送数据
{                                                                  // 进入字节发送函数体
    uint8_t i;                                                     // 定义循环变量，用于依次发送 8 个数据位
    for (i = 0; i < 8; i++)                                       // 从最高位开始循环 8 次，每次发送一位数据
    {                                                              // 进入单个数据位发送循环
        MyI2C_W_SDA(Byte & (0x80 >> i));                           // 根据当前位是否为 1 决定释放 SDA 还是主动拉低 SDA
        MyI2C_W_SCL(1);                                            // 拉高 SCL，让从机在时钟高电平期间采样当前 SDA 数据
        MyI2C_W_SCL(0);                                            // 拉低 SCL，结束当前位传输并允许主机准备下一位
    }                                                              // 结束 8 位数据发送循环
}                                                                  // 结束发送一个字节函数
uint8_t MyI2C_ReceiveByte(void)                                    // 定义接收一个字节函数，并返回组合后的 8 位数据
{                                                                  // 进入字节接收函数体
    uint8_t i;                                                     // 定义循环变量，用于依次接收 8 个数据位
    uint8_t Byte = 0x00;                                           // 定义接收缓存并清零，后续通过按位或写入采样结果
    MyI2C_W_SDA(1);                                                // 释放 SDA，将数据线控制权交给从机输出数据
    for (i = 0; i < 8; i++)                                       // 循环 8 次，从最高位到最低位读取从机数据
    {                                                              // 进入单个数据位接收循环
        MyI2C_W_SCL(1);                                            // 拉高 SCL，通知从机保持当前位并允许主机采样 SDA
        if (MyI2C_R_SDA() == 1)                                   // 判断当前 SDA 是否为高电平，从而确定本位数据是否为 1
        {                                                          // 进入当前接收位为 1 的处理分支
            Byte |= (0x80 >> i);                                  // 将接收缓存中对应位设置为 1，同时保留其他已接收位
        }                                                          // 结束当前接收位为 1 的处理分支
        MyI2C_W_SCL(0);                                            // 拉低 SCL，结束当前位采样并让从机准备下一位
    }                                                              // 结束 8 位数据接收循环
    return Byte;                                                   // 返回完整接收到的一个字节
}                                                                  // 结束接收一个字节函数
void MyI2C_SendAck(uint8_t AckBit)                                 // 定义主机发送应答位函数，AckBit 为 0 时发送 ACK
{                                                                  // 进入发送应答函数体
    MyI2C_W_SDA(AckBit);                                           // 将应答值放到 SDA，0 表示继续读取，1 表示结束读取
    MyI2C_W_SCL(1);                                                // 拉高 SCL，使从机在第 9 个时钟周期读取主机应答
    MyI2C_W_SCL(0);                                                // 拉低 SCL，结束应答位传输
}                                                                  // 结束发送应答函数
uint8_t MyI2C_ReceiveAck(void)                                     // 定义主机接收从机应答位函数
{                                                                  // 进入接收应答函数体
    uint8_t AckBit;                                                // 定义变量，用于保存从机返回的 ACK 或 NACK
    MyI2C_W_SDA(1);                                                // 释放 SDA，避免主机继续驱动数据线而妨碍从机应答
    MyI2C_W_SCL(1);                                                // 拉高 SCL，让主机在第 9 个时钟周期读取从机应答
    AckBit = MyI2C_R_SDA();                                        // 读取 SDA 电平，0 表示从机应答，1 表示未应答
    MyI2C_W_SCL(0);                                                // 拉低 SCL，结束应答位读取并准备后续传输
    return AckBit;                                                 // 返回应答结果，便于上层判断通信是否成功
}                                                                  // 结束接收从机应答函数
```

### 5. MPU6050.c

```c
#include "stm32f10x.h"                                             // 引入标准外设库基础类型和芯片定义
#include "MyI2C.h"                                                 // 引入软件 I2C 基本时序函数，作为器件驱动的通信底层
#include "MPU6050.h"                                               // 引入 MPU6050 驱动对外函数声明
#include "MPU6050_Reg.h"                                           // 引入 MPU6050 常用寄存器地址宏，避免直接使用魔法数字
#define MPU6050_ADDRESS 0xD0                                       // 定义包含写方向位的 8 位地址，AD0 为低时由 7 位地址 0x68 左移得到
void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)            // 定义向指定 MPU6050 寄存器写入一个字节的函数
{                                                                  // 进入指定寄存器写函数体
    MyI2C_Start();                                                 // 产生起始条件，通知总线上的从机开始一次新的通信
    MyI2C_SendByte(MPU6050_ADDRESS);                               // 发送从机地址和写方向位，选择 MPU6050 并声明后续为写操作
    MyI2C_ReceiveAck();                                            // 接收从机应答，课程基础实现中暂不对返回值做错误处理
    MyI2C_SendByte(RegAddress);                                    // 发送目标寄存器地址，设置 MPU6050 内部寄存器指针
    MyI2C_ReceiveAck();                                            // 接收从机对寄存器地址字节的应答
    MyI2C_SendByte(Data);                                          // 发送需要写入目标寄存器的数据
    MyI2C_ReceiveAck();                                            // 接收从机对数据字节的应答，确认本字节已被接收
    MyI2C_Stop();                                                  // 产生终止条件，结束本次指定寄存器写操作并释放总线
}                                                                  // 结束指定寄存器写函数
uint8_t MPU6050_ReadReg(uint8_t RegAddress)                        // 定义从指定 MPU6050 寄存器读取一个字节的函数
{                                                                  // 进入指定寄存器读函数体
    uint8_t Data;                                                  // 定义变量，用于暂存从目标寄存器读取的数据
    MyI2C_Start();                                                 // 产生第一次起始条件，先进入写阶段以指定寄存器地址
    MyI2C_SendByte(MPU6050_ADDRESS);                               // 发送 MPU6050 写地址，使主机可以写入内部寄存器指针
    MyI2C_ReceiveAck();                                            // 接收从机对写地址的应答
    MyI2C_SendByte(RegAddress);                                    // 发送待读取的寄存器地址，定位 MPU6050 内部寄存器
    MyI2C_ReceiveAck();                                            // 接收从机对寄存器地址的应答
    MyI2C_Start();                                                 // 产生重复起始条件，在不释放总线的情况下切换到读阶段
    MyI2C_SendByte(MPU6050_ADDRESS | 0x01);                        // 将最低位置 1 得到读地址 0xD1，通知从机向主机发送数据
    MyI2C_ReceiveAck();                                            // 接收从机对读地址的应答
    Data = MyI2C_ReceiveByte();                                    // 接收目标寄存器返回的一个字节并保存
    MyI2C_SendAck(1);                                              // 主机发送 NACK，表示本次只读取一个字节且不再继续接收
    MyI2C_Stop();                                                  // 产生终止条件，结束本次指定寄存器读操作并释放总线
    return Data;                                                   // 将读取到的寄存器数据返回给调用者
}                                                                  // 结束指定寄存器读函数
void MPU6050_Init(void)                                            // 定义 MPU6050 初始化函数
{                                                                  // 进入 MPU6050 初始化函数体
    MyI2C_Init();                                                  // 初始化软件 I2C GPIO，并让 SCL、SDA 回到总线空闲高电平
    MPU6050_WriteReg(MPU6050_PWR_MGMT_1, 0x01);                    // 解除睡眠并选择 X 轴陀螺仪 PLL 作为时钟源，提高时钟稳定性
    MPU6050_WriteReg(MPU6050_PWR_MGMT_2, 0x00);                    // 取消六个测量轴的待机状态，使加速度计和陀螺仪全部工作
    MPU6050_WriteReg(MPU6050_SMPLRT_DIV, 0x09);                    // 将采样率分频值设为 9，在常用配置下得到约 100Hz 输出采样率
    MPU6050_WriteReg(MPU6050_CONFIG, 0x06);                        // 配置数字低通滤波器，降低高频噪声并限制有效带宽
    MPU6050_WriteReg(MPU6050_GYRO_CONFIG, 0x18);                   // 将陀螺仪满量程设置为正负 2000 度每秒
    MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, 0x18);                  // 将加速度计满量程设置为正负 16g
}                                                                  // 结束 MPU6050 初始化函数
uint8_t MPU6050_GetID(void)                                        // 定义读取 MPU6050 身份标识的函数
{                                                                  // 进入芯片 ID 读取函数体
    return MPU6050_ReadReg(MPU6050_WHO_AM_I);                      // 读取 WHO_AM_I 寄存器并返回，正常情况下通常得到 0x68
}                                                                  // 结束芯片 ID 读取函数
void MPU6050_GetData(int16_t *AccX, int16_t *AccY, int16_t *AccZ, int16_t *GyroX, int16_t *GyroY, int16_t *GyroZ) // 定义读取三轴加速度和三轴角速度原始值的函数
{                                                                  // 进入六轴数据读取函数体
    uint8_t DataH;                                                 // 定义高字节缓存，用于暂存每个 16 位测量值的高 8 位
    uint8_t DataL;                                                 // 定义低字节缓存，用于暂存每个 16 位测量值的低 8 位
    DataH = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_H);                 // 读取 X 轴加速度原始值的高字节
    DataL = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_L);                 // 读取 X 轴加速度原始值的低字节
    *AccX = (int16_t)((DataH << 8) | DataL);                       // 将高低字节拼接为有符号 16 位 X 轴加速度原始值
    DataH = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_H);                 // 读取 Y 轴加速度原始值的高字节
    DataL = MPU6050_ReadReg(MPU6050_ACCEL_YOUT_L);                 // 读取 Y 轴加速度原始值的低字节
    *AccY = (int16_t)((DataH << 8) | DataL);                       // 将高低字节拼接为有符号 16 位 Y 轴加速度原始值
    DataH = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_H);                 // 读取 Z 轴加速度原始值的高字节
    DataL = MPU6050_ReadReg(MPU6050_ACCEL_ZOUT_L);                 // 读取 Z 轴加速度原始值的低字节
    *AccZ = (int16_t)((DataH << 8) | DataL);                       // 将高低字节拼接为有符号 16 位 Z 轴加速度原始值
    DataH = MPU6050_ReadReg(MPU6050_GYRO_XOUT_H);                  // 读取 X 轴角速度原始值的高字节
    DataL = MPU6050_ReadReg(MPU6050_GYRO_XOUT_L);                  // 读取 X 轴角速度原始值的低字节
    *GyroX = (int16_t)((DataH << 8) | DataL);                      // 将高低字节拼接为有符号 16 位 X 轴角速度原始值
    DataH = MPU6050_ReadReg(MPU6050_GYRO_YOUT_H);                  // 读取 Y 轴角速度原始值的高字节
    DataL = MPU6050_ReadReg(MPU6050_GYRO_YOUT_L);                  // 读取 Y 轴角速度原始值的低字节
    *GyroY = (int16_t)((DataH << 8) | DataL);                      // 将高低字节拼接为有符号 16 位 Y 轴角速度原始值
    DataH = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_H);                  // 读取 Z 轴角速度原始值的高字节
    DataL = MPU6050_ReadReg(MPU6050_GYRO_ZOUT_L);                  // 读取 Z 轴角速度原始值的低字节
    *GyroZ = (int16_t)((DataH << 8) | DataL);                      // 将高低字节拼接为有符号 16 位 Z 轴角速度原始值
}                                                                  // 结束六轴原始数据读取函数
```

## 关键知识点

### 1. 软件 I2C 的实现原理

#### 原理

软件 I2C，也称为 GPIO 模拟 I2C或“位操作 I2C”，不依赖 STM32 内部的 I2C 外设。程序直接控制两个普通 GPIO，按照 I2C 协议规定的电平变化顺序产生 SCL 和 SDA 波形。

I2C 传输并不是简单地“发送高低电平”，而是由若干基本时序单元拼接组成：

```text
起始 → 地址+方向 → 应答 → 寄存器地址 → 应答 → 数据 → 应答 → 终止
```

指定地址读取通常需要两段方向不同的传输：

```text
起始 → 写地址 → 寄存器地址 → 重复起始 → 读地址 → 接收数据 → NACK → 终止
```

#### 特点

- 可以选择几乎任意普通 GPIO，布线灵活。
- 代码过程直观，适合学习 I2C 的底层时序。
- 不占用 STM32 的硬件 I2C 外设资源。
- CPU 必须参与每一个时钟和数据位的控制。
- 时序速度、占空比和稳定性通常不如硬件 I2C。
- 容易通过修改代码加入延时、超时和总线恢复流程。

#### 面试易问

**Q：软件 I2C 和硬件 I2C 有什么区别？**

A：软件 I2C 由 CPU 控制 GPIO 模拟时序，灵活但占用 CPU、速度较低；硬件 I2C 由片上外设自动产生时序，效率和稳定性更高，但引脚和外设资源受芯片限制，状态机与错误处理也更复杂。

**Q：软件 I2C 为什么可以使用任意 GPIO？**

A：因为起始、终止、时钟和数据传输都由程序直接改变 GPIO 电平完成，不需要把引脚连接到内部 I2C 外设。

#### 易错点

- 只照搬函数名，却不理解每次 SDA 变化应发生在 SCL 的高电平还是低电平阶段。
- GPIO 翻转过快，而从机、线路电容或上拉电阻无法满足上升时间要求。
- 没有检查 ACK，器件不响应时程序仍继续执行，导致读取结果看似随机。
- 软件延时被编译器优化或系统主频变化后，实际总线频率失控。

---

### 2. 开漏输出与上拉电阻

#### 原理

I2C 的 SDA 和 SCL 通常采用开漏结构。开漏输出内部只有下拉 MOSFET：

- 写 0：MOSFET 导通，线路被主动拉低。
- 写 1：MOSFET 关闭，引脚进入释放状态。
- 高电平：由外部上拉电阻将总线拉高。

这种结构允许多个器件连接在同一根线上。只要任意器件拉低，总线就是低电平；只有所有器件都释放，总线才会变为高电平。

#### 特点

- 避免不同器件同时输出高、低电平造成硬短路。
- 支持多从机和多主机共享总线。
- 可以实现“线与”逻辑和仲裁。
- 上升沿速度由上拉电阻与总线电容共同决定。
- 上拉电阻太大时上升慢，太小时低电平电流和功耗增加。

#### 面试易问

**Q：为什么 I2C 不能直接使用普通推挽输出？**

A：多个器件共用 SDA 时，如果一个推挽输出高电平、另一个输出低电平，就会产生输出冲突和大电流。开漏输出只主动拉低，释放状态由上拉电阻统一产生高电平，可避免硬冲突。

**Q：代码中的 `SDA=1` 为什么叫“释放 SDA”？**

A：在开漏模式下，写 1 会关闭内部下拉 MOSFET，引脚不再主动驱动高电平，而是进入高阻释放状态。

#### 易错点

- 没有上拉电阻，导致 SDA/SCL 无法稳定回到高电平。
- 模块已自带上拉，又外接过小阻值并联，造成总线低电平电流过大。
- 把开漏写 1 理解成推挽方式的主动输出高电平。
- 使用长杜邦线、多个模块和较高频率，却没有重新评估上拉电阻与总线电容。

---

### 3. 起始、终止和数据有效性

#### 原理

I2C 对 SDA 变化时机有严格规定：

- SCL 高电平期间，SDA 从高变低：起始条件。
- SCL 高电平期间，SDA 从低变高：终止条件。
- 普通数据传输时，SDA 应在 SCL 低电平期间改变。
- SCL 高电平期间，SDA 应保持稳定，接收方在此期间采样。

因此，同一个 SDA 跳变在不同 SCL 状态下可能代表“数据变化”，也可能代表“开始/结束通信”。

#### 特点

- 起始条件用于占用总线并同步从机状态机。
- 重复起始可以在不释放总线的情况下改变通信方向。
- 终止条件用于释放总线，使其他主机或下一次通信可以开始。
- 每个字节固定包含 8 个数据位和第 9 个应答位。

#### 面试易问

**Q：什么是重复起始条件？**

A：主机在没有先发送终止条件的情况下再次发送起始条件。它常用于寄存器读取：先以写方向发送寄存器地址，再用重复起始切换到读方向。

**Q：为什么数据不能在 SCL 高电平期间随意变化？**

A：接收方通常在 SCL 高电平期间采样 SDA。此时变化会被解释为起始、终止或错误数据。

#### 易错点

- 起始函数中先拉低 SCL，再拉低 SDA，未形成标准起始条件。
- 终止函数中 SDA 已经是高电平，缺少明确的低到高跳变。
- 发送下一位前没有先拉低 SCL，导致 SDA 在高电平阶段变化。
- 读取寄存器时发送终止后重新起始虽然可能可用，但与重复起始的标准访问流程不一致。

---

### 4. ACK 与 NACK 应答机制

#### 原理

每发送完 8 位数据，发送方释放 SDA，接收方在第 9 个时钟周期返回一个应答位：

- SDA 为低：ACK，表示本字节已接收，可以继续。
- SDA 为高：NACK，表示未应答、传输结束或器件不存在。

写操作时，MPU6050 应对设备地址、寄存器地址和数据字节分别返回 ACK。读操作时，主机在还要继续接收数据时返回 ACK；读取最后一个字节后返回 NACK，再发送终止条件。

#### 特点

- ACK 是判断器件是否在线的最直接依据之一。
- NACK 不一定代表故障，也可以由主机用于正常结束读取。
- ACK 检查可以快速定位地址错误、接线错误和器件未上电。
- 完整驱动应为等待和应答加入超时，避免异常时死循环。

#### 面试易问

**Q：读取最后一个字节后为什么要发送 NACK？**

A：NACK 告诉从机主机不再需要更多数据，从机应释放 SDA，随后主机才能发送终止条件。

**Q：从机地址正确但仍然 NACK，可能有哪些原因？**

A：器件未供电、没有共地、SCL/SDA 接反、上拉缺失、总线被拉低、时序过快、器件还未完成上电启动，或者地址格式使用错误。

#### 易错点

- 把 ACK 的低电平误判为 1。
- 主机读取最后一字节后仍发送 ACK，导致从机继续准备数据。
- 忽略所有 ACK 返回值，使程序无法区分“读到 0”与“根本没有从机响应”。
- 从机 NACK 后未及时停止传输和释放总线。

---

### 5. 7 位地址与 8 位地址

#### 原理

MPU6050 的标准 I2C 从机地址是 7 位地址：

- AD0 = 0：地址为 `0x68`
- AD0 = 1：地址为 `0x69`

在线上传输的第一个字节由“7 位地址 + 1 位读写方向”组成。因此 AD0 为低时：

```text
写地址：0x68 << 1 | 0 = 0xD0
读地址：0x68 << 1 | 1 = 0xD1
```

课程代码直接定义 `0xD0`，表示它使用的是已经包含方向位位置的 8 位写地址表达方式。

#### 特点

- 数据手册通常给出 7 位地址。
- 某些底层驱动函数要求传入 7 位地址。
- 某些示例代码使用左移后的 8 位地址。
- 两种写法都可以正确，但必须与底层 API 约定一致。

#### 面试易问

**Q：为什么 MPU6050 地址有时写 `0x68`，有时写 `0xD0`？**

A：`0x68` 是 7 位从机地址；`0xD0` 是将 `0x68` 左移一位并在最低位填入写方向位后的总线地址字节。

**Q：HAL 库设备地址参数应该传哪个？**

A：要查看具体 HAL API 的约定。STM32 HAL 的常见接口通常要求传入左移后的地址，而很多其他平台 API 要求 7 位地址，不能只凭数值猜测。

#### 易错点

- 把 `0x68` 直接传给要求 8 位地址的底层函数，导致寻址错误。
- 已经使用 `0xD0` 后又左移一次，得到完全错误的地址。
- AD0 实际被拉高，但代码仍使用 `0x68/0xD0`。
- 将 `WHO_AM_I` 返回的 `0x68` 误认为它一定等于当前完整从机地址；AD0 的最低地址位不体现在该寄存器返回值中。

### 6. MPU6050 寄存器读写分层

#### 原理

MPU6050 是典型的寄存器型外设。应用程序不直接控制其内部电路，而是通过 I2C 访问寄存器：

- 写配置寄存器：改变电源、滤波、量程和采样率。
- 读状态寄存器：检查芯片状态与身份。
- 读数据寄存器：取得加速度、温度和角速度原始值。

程序按三层划分：

1. `MyI2C.c`：只负责总线时序，不理解 MPU6050。
2. `MPU6050.c`：调用 I2C 时序，实现寄存器访问和器件功能。
3. `main.c`：只调用初始化与获取数据接口，不关心通信细节。

#### 特点

- 通信层可复用于其他 I2C 传感器。
- 器件层屏蔽寄存器地址和初始化流程。
- 应用层代码简洁，便于更换显示方式或控制算法。
- 分层后更容易用逻辑分析仪定位问题属于总线层还是器件层。

#### 面试易问

**Q：为什么驱动代码要分层？**

A：分层能降低模块耦合，提高复用性和可测试性。更换 GPIO、软件/硬件 I2C 或上层应用时，只需修改对应层。

**Q：`MPU6050_Reg.h` 单独存在有什么意义？**

A：它集中管理寄存器地址，使代码可读、便于查手册，并避免大量难以理解的十六进制魔法数字。

#### 易错点

- 在 `main.c` 中到处直接写寄存器地址，导致应用逻辑与器件细节强耦合。
- 同一个地址宏在多个文件中重复定义，修改时产生不一致。
- 器件驱动依赖 OLED 或串口输出，使底层模块无法复用。
- 软件 I2C 与硬件 I2C 函数混用，导致地址格式和状态处理不一致。

### 7. MPU6050 初始化寄存器

#### 原理

MPU6050 上电后默认处于睡眠状态，因此必须先写电源管理寄存器解除睡眠。随后配置采样率、数字低通滤波器和满量程。

本节参考初始化值如下：

| 寄存器 | 写入值 | 作用 |
|---|---:|---|
| `PWR_MGMT_1` | `0x01` | 解除睡眠，选择 X 轴陀螺仪 PLL 时钟 |
| `PWR_MGMT_2` | `0x00` | 六个测量轴均不待机 |
| `SMPLRT_DIV` | `0x09` | 设置采样率分频 |
| `CONFIG` | `0x06` | 设置数字低通滤波器 |
| `GYRO_CONFIG` | `0x18` | 陀螺仪量程设为 ±2000°/s |
| `ACCEL_CONFIG` | `0x18` | 加速度计量程设为 ±16g |

#### 特点

- 量程越大，单位原始码对应的物理量越大，分辨率相对降低。
- 量程越小，测量更细腻，但更容易在大运动时饱和。
- 低通滤波可以降低高频噪声，但也会增加相位延迟。
- 采样率应根据控制周期、噪声和总线读取能力综合设置。

#### 面试易问

**Q：为什么 MPU6050 上电后读不到合理运动数据？**

A：器件默认可能处于睡眠状态，需要先清除 `PWR_MGMT_1` 的睡眠位并选择合适时钟源。

**Q：量程和分辨率如何取舍？**

A：量程越大越不容易饱和，但每个 LSB 表示的物理量更大、细节分辨率更低；量程越小则相反。

#### 易错点

- 忘记解除睡眠，导致数据不更新或表现异常。
- 修改量程后仍使用旧的灵敏度系数换算物理量。
- 只看寄存器写入代码，不核对位定义，误把保留位写成 1。
- 采样率设置很高，却使用低速软件 I2C 和频繁 OLED 刷新，导致应用层更新速度跟不上。

---

### 8. 16 位原始数据拼接与符号

#### 原理

MPU6050 每个测量轴使用两个连续的 8 位寄存器保存一个 16 位二进制补码结果，高字节在前、低字节在后。

拼接方式为：

```text
Raw = (HighByte << 8) | LowByte
```

拼接后应转换或保存为 `int16_t`。当最高位为 1 时，结果代表负数。

在本节配置下，常见物理量换算为：

```text
加速度 g = 原始值 / 2048
角速度 °/s = 原始值 / 16.4
```

#### 特点

- 原始值范围为 `-32768 ~ 32767`。
- 高低字节顺序不能颠倒。
- 必须使用有符号类型解释二进制补码。
- 静止时并非所有轴都为 0，重力会投影到加速度计坐标轴。
- 陀螺仪静止时也可能存在零偏和噪声。

#### 面试易问

**Q：为什么读取到的原始值要使用 `int16_t`？**

A：加速度和角速度都有正负方向，寄存器使用 16 位二进制补码表示，使用无符号类型会把负值解释成很大的正数。

**Q：平放时 Z 轴为什么不是 0？**

A：加速度计会测到重力加速度。若 Z 轴与重力方向平行，Z 轴应接近 ±1g 对应的原始值，而不是 0。

#### 易错点

- 使用 `uint16_t` 保存数据，负方向读数显示为大正数。
- 先将 8 位高字节左移但未正确提升类型，在某些写法中发生符号或宽度问题。
- 把高低字节顺序拼反，数据幅值和符号完全异常。
- 未进行零偏校准，就直接把原始陀螺仪数据积分为角度，导致漂移快速累积。

### 9. `WHO_AM_I` 自检

#### 原理

`WHO_AM_I` 寄存器地址为 `0x75`，默认值通常为 `0x68`。读取该寄存器是验证通信链路的低成本方法：

```text
供电 → 共地 → 上拉 → GPIO 时序 → 从机地址 → 寄存器地址 → 数据读取
```

如果能够稳定读出 `0x68`，说明最基础的软件 I2C 寻址和单字节读流程大概率正确。

#### 特点

- 不受传感器姿态影响，结果应稳定。
- 比直接观察六轴数据更适合作为第一步调试。
- 能验证读操作，但不能完全证明所有配置写入都正确。
- AD0 改变从机地址时，`WHO_AM_I` 默认值仍通常显示 `0x68`。

#### 面试易问

**Q：读出 `WHO_AM_I = 0x68` 是否说明驱动完全正确？**

A：只能说明基础寻址和寄存器读取基本正常。仍需检查写寄存器、连续读取、数据更新、量程和换算是否正确。

**Q：读到 `0xFF` 或 `0x00` 通常意味着什么？**

A：`0xFF` 常见于 SDA 被上拉且从机未驱动；`0x00` 可能是总线被拉低、读取时序错误或错误寄存器值，需要结合 ACK 和波形判断。

#### 易错点

- 只显示十进制数，看到 `104` 却误以为 ID 错误；`104` 的十六进制就是 `0x68`。
- 读取结果偶尔正确就认为总线可靠，忽略接触不良和边沿过慢。
- 未检查 ACK，仅凭最终 ID 猜测故障。
- 将 `WHO_AM_I` 与产品序列号或唯一芯片 ID 混淆。

## 本节核心记忆

```text
软件 I2C = 普通 GPIO + 按协议手动产生 SCL/SDA 时序
```

```text
I2C 高电平不是器件主动推高，而是所有器件释放后由上拉电阻拉高
```

```text
MPU6050 的 7 位地址通常为 0x68
8 位写地址为 0xD0，8 位读地址为 0xD1
```

```text
指定寄存器读 = 写入寄存器地址 + 重复起始 + 切换读方向 + 接收数据
```

```text
驱动分层 = 通信层 MyI2C + 器件层 MPU6050 + 应用层 main
```

```text
六轴原始数据是 16 位有符号数：高字节在前，低字节在后
```

## 开发过程总结

### 问题 1：OLED 显示的 ID 不是 `0x68`

现象：

- ID 显示为 `00`、`FF` 或不断变化。
- 六轴数据无规律或完全不更新。
- 程序可以编译下载，但传感器没有正确响应。

排查过程：

1. 检查 MPU6050 是否正确供电，STM32 与模块是否共地。
2. 检查 SCL、SDA 是否分别接到 PB10、PB11，避免接反。
3. 检查模块是否带上拉电阻，空闲状态下 SCL、SDA 是否均为高电平。
4. 检查 AD0 电平，确认从机地址是 `0x68` 还是 `0x69`。
5. 检查代码使用的是 7 位地址还是左移后的 8 位地址。
6. 检查 `MyI2C_ReceiveAck()` 是否能收到低电平 ACK。
7. 使用逻辑分析仪观察起始、地址、应答和寄存器地址是否正确。

解决方案：

- 修正供电、共地和 SCL/SDA 接线。
- 根据 AD0 状态修改设备地址。
- 在驱动中加入 ACK 返回值检查，定位具体在哪个字节出现 NACK。
- 若线路较长或波形上升慢，降低软件 I2C 速度并调整上拉电阻。

### 问题 2：SCL、SDA 一直为低电平

现象：

- 示波器或逻辑分析仪看到总线长期保持低电平。
- 软件 I2C 无法产生正常起始条件。
- 重新下载程序后问题仍可能存在。

排查过程：

1. 检查 GPIO 是否错误配置为推挽输出并持续输出 0。
2. 检查初始化结束时是否调用 `MyI2C_W_SCL(1)` 和 `MyI2C_W_SDA(1)`。
3. 断开 MPU6050，判断是主机代码还是从机模块拉低总线。
4. 检查 SDA/SCL 是否短路到 GND。
5. 检查上一次通信是否在中途复位，使从机仍等待后续时钟。

解决方案：

- 使用开漏输出并在空闲时释放两根总线。
- 修复短路和接线错误。
- 增加总线恢复流程：释放 SDA 后手动输出若干个 SCL 脉冲，再发送终止条件。
- 为所有等待过程加入超时，避免软件永久卡死。

### 问题 3：能够读出 ID，但六轴数据异常

现象：

- ID 稳定为 `0x68`。
- 数据始终为 0、接近固定值或变化幅度不合理。
- 旋转模块后陀螺仪数据没有明显变化。

排查过程：

1. 检查是否调用 `MPU6050_Init()` 并成功写入 `PWR_MGMT_1`。
2. 读回关键配置寄存器，确认写入值确实生效。
3. 检查数据寄存器地址是否正确。
4. 检查高低字节是否按正确顺序拼接。
5. 检查变量是否使用 `int16_t`。
6. 检查 OLED 显示函数的位数和符号显示是否正确。

解决方案：

- 解除睡眠并启用所有测量轴。
- 修正寄存器地址和高低字节拼接。
- 将数据变量改为 16 位有符号类型。
- 先通过串口打印十六进制原始字节，逐级确认读取和显示环节。

### 问题 4：数值跳动很大

现象：

- 模块静止时数据仍持续抖动。
- OLED 刷新很快，数字看起来难以观察。
- 电机运行时传感器噪声明显增大。

排查过程：

1. 确认这是 MEMS 传感器的正常噪声，还是供电和机械振动造成的异常。
2. 检查 `CONFIG` 数字低通滤波设置。
3. 检查供电是否稳定，模块附近是否存在电机等干扰源。
4. 检查杜邦线是否过长、接触是否可靠。
5. 比较原始数据、滑动平均结果和低通滤波结果。

解决方案：

- 使用稳定电源和良好接地。
- 合理配置数字低通滤波器。
- 对显示数据加入滑动平均或一阶低通滤波。
- 将传感器远离电机和大电流开关器件，并改善机械固定。

### 问题 5：改变姿态后数据方向与预期相反

现象：

- 向正方向倾斜时某一轴显示负值。
- 不同模块安装方向下轴定义不一致。
- 后续姿态解算中的角度方向与机械坐标系相反。

排查过程：

1. 查看模块 PCB 上标注的 X、Y、Z 方向。
2. 明确传感器坐标系与设备机体坐标系的对应关系。
3. 确认显示的是原始数据，不是经过坐标变换后的结果。
4. 检查模块是否倒装或旋转安装。

解决方案：

- 在应用层进行轴交换和符号变换。
- 统一定义右手坐标系，并在项目文档中记录安装方向。
- 不要为了让显示“看起来正确”而修改底层寄存器读取顺序。

### 问题 6：软件 I2C 偶发通信失败

现象：

- 大多数时候数据正常，偶尔出现突变或 ID 错误。
- 开启编译优化、增加中断或改变系统主频后故障概率上升。
- 使用更长线缆后通信变得不稳定。

排查过程：

1. 测量 SCL、SDA 的高低电平和上升时间。
2. 检查软件时序是否依赖函数执行时间，而没有显式延时。
3. 检查高优先级中断是否在一个字节传输中间打断时序。
4. 检查上拉电阻是否与总线电容匹配。
5. 检查 ACK 并记录失败发生在哪个阶段。

解决方案：

- 在关键电平切换之间加入稳定的微秒级延时。
- 降低总线频率。
- 在需要时使用短临界区保护单个时序单元。
- 加入超时、重试和总线恢复机制。
- 对实时性和可靠性要求较高的项目，评估改用硬件 I2C。

## 结果展示

> 实验 1：上电并初始化后，OLED 的 ID 区域稳定显示 `68`，说明 STM32 已经能够通过软件 I2C 正确读取 MPU6050 的 `WHO_AM_I` 寄存器。✅

> 实验 2：静止放置模块时，三轴加速度中与重力方向接近的一轴具有明显非零值，其余轴在零点附近带有少量噪声。✅

> 实验 3：旋转或晃动模块时，AX、AY、AZ、GX、GY、GZ 六个原始数据随运动方向和速度发生变化。✅

> 实验 4：改变模块姿态后，各轴数据符号和幅值按照传感器坐标方向变化，表明六轴寄存器读取与有符号拼接正常。✅

## 本节小结

本节通过软件 I2C 读取 MPU6050，完成了从物理总线到应用显示的完整驱动链路。

最重要的知识点是：

```text
GPIO 开漏输出 + 上拉电阻
        ↓
I2C 六个基本时序单元
        ↓
指定寄存器读写
        ↓
MPU6050 初始化和六轴数据读取
```

学习完本节后，应能够：

- 根据 SCL、SDA 波形解释 I2C 的起始、终止、数据和应答。
- 独立编写软件 I2C 的基础时序函数。
- 区分 7 位从机地址和带读写位的地址字节。
- 使用重复起始完成指定寄存器读取。
- 按模块化方式封装通信层、器件层和应用层。
- 正确拼接并解释 MPU6050 的 16 位有符号原始数据。
- 使用 `WHO_AM_I`、ACK 和逻辑分析仪逐级排查通信故障。

下一节通常会进入 STM32 的硬件 I2C 外设，重点比较由软件手动控制时序与硬件状态机自动完成通信之间的区别。
