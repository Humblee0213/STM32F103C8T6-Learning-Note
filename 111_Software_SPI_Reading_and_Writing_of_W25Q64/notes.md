## 实验概述

本实验基于 STM32F103C8T6 标准外设库，使用普通 GPIO 模拟 SPI 主机时序，驱动 W25Q64 串行 NOR Flash，实现以下功能：

1. 初始化软件 SPI 所需的 `SS`、`SCK`、`MOSI`、`MISO` 引脚。
2. 按 SPI 模式 0 交换一个字节。
3. 发送 `0x9F` 指令读取 JEDEC ID。
4. 执行写使能和忙状态轮询。
5. 擦除一个 4 KB 扇区。
6. 使用页编程指令写入一组数据。
7. 从指定地址读取数据，并通过 OLED 对比显示写入值和读回值。

本节的核心目标不是只记住几个 W25Q64 函数，而是理解分层驱动的设计方法：

```text
GPIO 电平操作
    ↓
软件 SPI 基本时序：Start / Stop / SwapByte
    ↓
W25Q64 指令时序：ReadID / WriteEnable / WaitBusy / Erase / Program / Read
    ↓
应用层测试：擦除 → 写入 → 读取 → 显示验证
```

W25Q64 是一颗 64 Mbit 串行 NOR Flash，换算后容量为 8 MB。其存储阵列常用组织方式如下：

| 层级 | 大小 | 数量 | 说明 |
|---|---:|---:|---|
| 芯片 | 8 MB | 1 | 地址范围约为 `0x000000 ~ 0x7FFFFF` |
| 块 | 64 KB | 128 | 可使用 64 KB 块擦除 |
| 扇区 | 4 KB | 2048 | 本实验使用 `0x20` 指令进行扇区擦除 |
| 页 | 256 B | 32768 | 页编程一次最多写入 256 字节 |
| 字节 | 8 bit | 8388608 | 使用 24 位地址定位 |

## 硬件连接

本实验常见接线如下，具体以开发板原理图和 W25Q64 模块丝印为准。

| 器件/信号 | STM32 引脚 | W25Q64 引脚/模块引脚 | 说明 |
|---|---:|---:|---|
| `SS / CS` | PA4 | `/CS` | 低电平选中 Flash，高电平结束一帧指令 |
| `SCK` | PA5 | `CLK` | 软件产生 SPI 时钟，本实验空闲时为低电平 |
| `MISO` | PA6 | `DO / IO1` | W25Q64 输出，STM32 输入 |
| `MOSI` | PA7 | `DI / IO0` | STM32 输出，W25Q64 输入 |
| 电源 | 3.3V | `VCC` | W25Q64JV 工作电压为 2.7V～3.6V，不可直接接 5V |
| 地 | GND | `GND` | STM32、Flash、OLED 必须共地 |
| 写保护 | 上拉至 3.3V | `/WP / IO2` | 常见模块已经上拉；裸芯片使用标准 SPI 时应保持高电平 |
| 保持/复位 | 上拉至 3.3V | `/HOLD / RESET / IO3` | 常见模块已经上拉；裸芯片使用标准 SPI 时应保持高电平 |
| OLED SCL（可选） | PB8 | OLED SCL | 沿用课程前面章节的软件 I2C OLED 接线 |
| OLED SDA（可选） | PB9 | OLED SDA | 用于显示 ID、写入值和读回值 |

> 注意：
>
> - W25Q64 模块必须使用 **3.3V 电源和 3.3V 逻辑电平**。
> - 如果使用裸芯片，`/WP` 与 `/HOLD` 不能悬空，通常通过上拉电阻接至 3.3V。
> - PA4～PA7 在本实验中由软件直接控制，并未启用 STM32 的 SPI1 外设。
> - 使用逻辑分析仪时，至少同时观察 `CS`、`SCK`、`MOSI`、`MISO` 四路信号。

### 2. MySPI.c

```c
#include "MySPI.h"                                     // 引入本模块头文件，获得函数声明和 STM32 库定义

static void MySPI_W_SS(uint8_t BitValue)               // 定义 SS 写电平函数，将片选操作封装在底层
{                                                      // 开始 SS 写电平函数体
    GPIO_WriteBit(GPIOA, GPIO_Pin_4,                   // 向 GPIOA 的 PA4 写入指定电平，PA4 连接 W25Q64 的 CS
                  BitValue ? Bit_SET : Bit_RESET);     // 将任意非零值转换为标准 Bit_SET，零值转换为 Bit_RESET
}                                                      // 结束 SS 写电平函数体

static void MySPI_W_SCK(uint8_t BitValue)              // 定义 SCK 写电平函数，用软件产生 SPI 时钟
{                                                      // 开始 SCK 写电平函数体
    GPIO_WriteBit(GPIOA, GPIO_Pin_5,                   // 向 GPIOA 的 PA5 写入指定电平，PA5 连接 W25Q64 的 CLK
                  BitValue ? Bit_SET : Bit_RESET);     // 规范化电平参数，避免把非 0/1 数值直接强制转换为枚举
}                                                      // 结束 SCK 写电平函数体

static void MySPI_W_MOSI(uint8_t BitValue)             // 定义 MOSI 写电平函数，用于向从机发送一位数据
{                                                      // 开始 MOSI 写电平函数体
    GPIO_WriteBit(GPIOA, GPIO_Pin_7,                   // 向 GPIOA 的 PA7 写入指定电平，PA7 连接 W25Q64 的 DI
                  BitValue ? Bit_SET : Bit_RESET);     // 根据 BitValue 输出高电平或低电平
}                                                      // 结束 MOSI 写电平函数体

static uint8_t MySPI_R_MISO(void)                      // 定义 MISO 读电平函数，用于读取从机输出的一位数据
{                                                      // 开始 MISO 读电平函数体
    return GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_6);   // 读取 PA6 输入电平并返回，PA6 连接 W25Q64 的 DO
}                                                      // 结束 MISO 读电平函数体

void MySPI_Init(void)                                  // 定义软件 SPI 初始化函数
{                                                      // 开始软件 SPI 初始化函数体
    GPIO_InitTypeDef GPIO_InitStructure;               // 定义 GPIO 初始化结构体，用于配置模式、引脚和速度

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA,       // 选择 GPIOA 外设时钟，软件 SPI 的四根线均位于 GPIOA
                           ENABLE);                    // 使能 GPIOA 时钟，否则无法正常配置和操作端口

    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;   // 将输出线配置为通用推挽输出，可主动输出高低电平
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_4 |         // 将 PA4 加入本次初始化，作为 SS/CS 输出
                                  GPIO_Pin_5 |         // 将 PA5 加入本次初始化，作为 SCK 输出
                                  GPIO_Pin_7;          // 将 PA7 加入本次初始化，作为 MOSI 输出
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz; // 设置 GPIO 输出速度等级，满足软件 SPI 翻转需求
    GPIO_Init(GPIOA, &GPIO_InitStructure);             // 将以上输出配置写入 GPIOA 对应寄存器

    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;      // 将输入线配置为上拉输入，避免从机未驱动时引脚悬空
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_6;          // 选择 PA6 作为 MISO 输入引脚
    GPIO_Init(GPIOA, &GPIO_InitStructure);             // 将 MISO 输入配置写入 GPIOA 对应寄存器

    MySPI_W_SS(1);                                     // 默认拉高 SS，使 W25Q64 处于未选中状态
    MySPI_W_SCK(0);                                    // 模式 0 下时钟空闲电平为低电平
    MySPI_W_MOSI(0);                                   // 将 MOSI 初始化为低电平，得到确定的总线初始状态
}                                                      // 结束软件 SPI 初始化函数体

void MySPI_Start(void)                                 // 定义 SPI 起始函数
{                                                      // 开始 SPI 起始函数体
    MySPI_W_SS(0);                                     // 拉低 SS，选中 W25Q64 并开始一帧连续指令时序
}                                                      // 结束 SPI 起始函数体

void MySPI_Stop(void)                                  // 定义 SPI 终止函数
{                                                      // 开始 SPI 终止函数体
    MySPI_W_SS(1);                                     // 拉高 SS，使 W25Q64 锁存并执行刚刚接收的完整指令
}                                                      // 结束 SPI 终止函数体

uint8_t MySPI_SwapByte(uint8_t ByteSend)               // 定义 SPI 字节交换函数，采用模式 0 且高位先行
{                                                      // 开始 SPI 字节交换函数体
    uint8_t i;                                         // 定义循环变量，用于依次处理 8 个数据位
    uint8_t ByteReceive = 0x00;                        // 定义接收字节并清零，后续逐位写入接收到的数据

    for (i = 0; i < 8; i++)                            // 循环 8 次，每次完成一位数据的发送和接收
    {                                                  // 开始单个数据位的交换过程
        MySPI_W_MOSI((ByteSend & (0x80 >> i)) != 0);   // 从最高位开始取出待发送位，并在上升沿前放到 MOSI
        MySPI_W_SCK(1);                                // 拉高 SCK 产生上升沿，主机与从机在该阶段采样输入数据

        if (MySPI_R_MISO() == 1)                       // 判断当前从 MISO 读取到的数据位是否为高电平
        {                                              // 开始接收位为 1 时的处理
            ByteReceive |= (uint8_t)(0x80 >> i);       // 将接收字节中对应位设置为 1，保持高位先行的顺序
        }                                              // 结束接收位为 1 时的处理

        MySPI_W_SCK(0);                                // 拉低 SCK 产生下降沿，为下一位数据准备新的输出
    }                                                  // 结束 8 位数据交换循环

    return ByteReceive;                                // 返回同时接收到的 8 位数据
}                                                      // 结束 SPI 字节交换函数体
```

### 3. W25Q64_Ins.h

```c
#ifndef __W25Q64_INS_H                                 // 判断是否尚未定义指令表头文件保护宏
#define __W25Q64_INS_H                                 // 定义指令表头文件保护宏，避免重复包含

#define W25Q64_WRITE_ENABLE                 0x06       // 写使能指令，将状态寄存器中的 WEL 位置 1
#define W25Q64_WRITE_DISABLE                0x04       // 写禁止指令，主动清除写使能锁存位
#define W25Q64_READ_STATUS_REGISTER_1       0x05       // 读取状态寄存器 1 指令，可读取 BUSY 和 WEL 等状态
#define W25Q64_WRITE_STATUS_REGISTER        0x01       // 写状态寄存器指令，可用于修改部分保护位
#define W25Q64_PAGE_PROGRAM                 0x02       // 页编程指令，在同一页内写入 1～256 字节
#define W25Q64_SECTOR_ERASE_4KB             0x20       // 4 KB 扇区擦除指令，将整个扇区恢复为 0xFF
#define W25Q64_READ_DATA                    0x03       // 普通数据读取指令，从指定 24 位地址开始连续读取
#define W25Q64_JEDEC_ID                     0x9F       // JEDEC ID 读取指令，返回厂商、类型和容量编码
#define W25Q64_DUMMY_BYTE                   0xFF       // 占位字节，主机读取数据时用于继续产生时钟

#endif                                                 // 结束指令表头文件保护条件编译
```

### 5. W25Q64.c

```c
#include "W25Q64.h"                                    // 引入 W25Q64 对外接口声明和基础整数类型
#include "W25Q64_Ins.h"                                // 引入 W25Q64 指令码宏定义
#include "MySPI.h"                                     // 引入软件 SPI 初始化和字节交换接口

void W25Q64_Init(void)                                 // 定义 W25Q64 初始化函数
{                                                      // 开始 W25Q64 初始化函数体
    MySPI_Init();                                      // 初始化 SS、SCK、MOSI、MISO 四根软件 SPI 引脚
}                                                      // 结束 W25Q64 初始化函数体

void W25Q64_ReadID(uint8_t *MID, uint16_t *DID)        // 定义 JEDEC ID 读取函数，通过输出参数返回三个 ID 字节
{                                                      // 开始 JEDEC ID 读取函数体
    MySPI_Start();                                     // 拉低 CS，开始一帧连续的 JEDEC ID 读取时序
    MySPI_SwapByte(W25Q64_JEDEC_ID);                   // 发送 0x9F 指令，通知芯片输出 JEDEC 标识
    *MID = MySPI_SwapByte(W25Q64_DUMMY_BYTE);          // 发送占位字节产生时钟，并接收厂商 ID
    *DID = MySPI_SwapByte(W25Q64_DUMMY_BYTE);          // 接收设备 ID 的高 8 位，即 Memory Type
    *DID <<= 8;                                        // 将已接收的高 8 位移动到 uint16_t 的高字节位置
    *DID |= MySPI_SwapByte(W25Q64_DUMMY_BYTE);         // 接收容量编码并合并到设备 ID 的低 8 位
    MySPI_Stop();                                      // 拉高 CS，结束 JEDEC ID 读取时序
}                                                      // 结束 JEDEC ID 读取函数体

void W25Q64_WriteEnable(void)                          // 定义写使能函数
{                                                      // 开始写使能函数体
    MySPI_Start();                                     // 拉低 CS，开始发送独立的写使能指令
    MySPI_SwapByte(W25Q64_WRITE_ENABLE);               // 发送 0x06，使状态寄存器中的 WEL 位变为 1
    MySPI_Stop();                                      // 拉高 CS，提交写使能指令并结束本帧
}                                                      // 结束写使能函数体

void W25Q64_WaitBusy(void)                             // 定义忙状态轮询函数
{                                                      // 开始忙状态轮询函数体
    uint32_t Timeout = 100000;                         // 设置软件超时计数，避免硬件异常时程序永久死循环

    MySPI_Start();                                     // 拉低 CS，开始连续读取状态寄存器 1
    MySPI_SwapByte(W25Q64_READ_STATUS_REGISTER_1);     // 发送 0x05 指令，选择读取状态寄存器 1

    while ((MySPI_SwapByte(W25Q64_DUMMY_BYTE) &        // 持续发送占位字节并读取状态寄存器的最新值
            0x01) == 0x01)                             // 屏蔽除 BUSY 位外的其他位，BUSY 为 1 表示芯片仍在操作
    {                                                  // 开始 BUSY 状态等待循环
        Timeout--;                                     // 每轮轮询减少超时计数
        if (Timeout == 0)                              // 判断是否达到预设的最大等待次数
        {                                              // 开始超时处理分支
            break;                                     // 超时后退出循环，避免主程序永久卡死
        }                                              // 结束超时处理分支
    }                                                  // 结束 BUSY 状态等待循环

    MySPI_Stop();                                      // 拉高 CS，结束状态寄存器连续读取时序
}                                                      // 结束忙状态轮询函数体

void W25Q64_PageProgram(uint32_t Address,              // 定义页编程函数，Address 为写入起始地址
                         uint8_t *DataArray,            // DataArray 指向待写入的数据
                         uint16_t Count)                // Count 表示本次写入的字节数
{                                                      // 开始页编程函数体
    uint16_t i;                                        // 定义循环变量，用于逐字节发送待写入数据

    if ((Count == 0) || (Count > 256))                 // 检查字节数是否处于页编程允许的 1～256 范围
    {                                                  // 开始非法长度处理分支
        return;                                        // 参数无效时直接返回，避免发出错误指令
    }                                                  // 结束非法长度处理分支

    if (((Address & 0xFF) + Count) > 256)              // 判断起始页内偏移加长度是否越过当前 256 字节页
    {                                                  // 开始跨页处理分支
        return;                                        // 本参考实现拒绝跨页写入，防止芯片页内回卷覆盖数据
    }                                                  // 结束跨页处理分支

    W25Q64_WriteEnable();                              // 每次页编程前先执行写使能，使 WEL 位置 1

    MySPI_Start();                                     // 拉低 CS，开始完整的页编程指令帧
    MySPI_SwapByte(W25Q64_PAGE_PROGRAM);               // 发送 0x02 页编程指令
    MySPI_SwapByte((uint8_t)(Address >> 16));          // 发送 24 位地址的高 8 位 A23～A16
    MySPI_SwapByte((uint8_t)(Address >> 8));           // 发送 24 位地址的中间 8 位 A15～A8
    MySPI_SwapByte((uint8_t)Address);                  // 发送 24 位地址的低 8 位 A7～A0

    for (i = 0; i < Count; i++)                        // 按顺序发送本次需要写入的全部数据字节
    {                                                  // 开始数据发送循环
        MySPI_SwapByte(DataArray[i]);                  // 发送数组中的第 i 个字节，接收值在写操作中无需使用
    }                                                  // 结束数据发送循环

    MySPI_Stop();                                      // 拉高 CS，芯片随后开始内部自定时页编程过程
    W25Q64_WaitBusy();                                 // 轮询 BUSY 位，确保编程完成后再允许后续操作
}                                                      // 结束页编程函数体

void W25Q64_SectorErase(uint32_t Address)              // 定义 4 KB 扇区擦除函数
{                                                      // 开始扇区擦除函数体
    W25Q64_WriteEnable();                              // 擦除属于写操作，执行前必须先发送写使能指令

    MySPI_Start();                                     // 拉低 CS，开始完整的扇区擦除指令帧
    MySPI_SwapByte(W25Q64_SECTOR_ERASE_4KB);           // 发送 0x20 指令，选择 4 KB 扇区擦除
    MySPI_SwapByte((uint8_t)(Address >> 16));          // 发送目标地址的高 8 位
    MySPI_SwapByte((uint8_t)(Address >> 8));           // 发送目标地址的中间 8 位
    MySPI_SwapByte((uint8_t)Address);                  // 发送目标地址的低 8 位，芯片据此确定目标扇区
    MySPI_Stop();                                      // 拉高 CS，芯片开始内部自定时擦除过程

    W25Q64_WaitBusy();                                 // 等待 BUSY 位清零，确保整个 4 KB 扇区擦除完成
}                                                      // 结束扇区擦除函数体

void W25Q64_ReadData(uint32_t Address,                 // 定义连续读取函数，Address 为读取起始地址
                      uint8_t *DataArray,               // DataArray 指向接收缓冲区
                      uint32_t Count)                   // Count 表示需要连续读取的字节数量
{                                                      // 开始连续读取函数体
    uint32_t i;                                        // 定义循环变量，用于逐字节保存读取结果

    MySPI_Start();                                     // 拉低 CS，开始完整的数据读取指令帧
    MySPI_SwapByte(W25Q64_READ_DATA);                  // 发送 0x03 普通读取指令
    MySPI_SwapByte((uint8_t)(Address >> 16));          // 发送读取起始地址的高 8 位
    MySPI_SwapByte((uint8_t)(Address >> 8));           // 发送读取起始地址的中间 8 位
    MySPI_SwapByte((uint8_t)Address);                  // 发送读取起始地址的低 8 位

    for (i = 0; i < Count; i++)                        // 根据 Count 连续读取指定数量的数据
    {                                                  // 开始连续读取循环
        DataArray[i] =                                 // 将本次读到的字节保存到接收数组对应位置
            MySPI_SwapByte(W25Q64_DUMMY_BYTE);         // 发送占位字节产生 8 个时钟，并接收 Flash 输出的数据
    }                                                  // 结束连续读取循环

    MySPI_Stop();                                      // 拉高 CS，结束本次连续读取操作
}                                                      // 结束连续读取函数体
```

## 关键知识点

### 1. 软件 SPI 与分层驱动

#### 原理

软件 SPI 也称位操作 SPI或 GPIO 模拟 SPI。程序不使用 STM32 内部 SPI 外设，而是直接控制 GPIO 电平，按照从机数据手册规定的顺序产生：

```text
CS 电平
SCK 上升沿/下降沿
MOSI 输出位
MISO 采样位
```

为了避免应用层直接操作每一个 GPIO，驱动通常分成三层：

```text
GPIO 层 → SPI 时序层 → W25Q64 指令层
```

- GPIO 层只负责写 `SS/SCK/MOSI` 和读 `MISO`。
- SPI 时序层只负责开始、停止和交换一个字节。
- W25Q64 指令层负责组织指令码、地址和数据。

#### 特点

- 引脚选择灵活，不受硬件 SPI 复用映射限制。
- 时序直观，适合理解 SPI 协议和调试波形。
- 可方便修改 CPOL、CPHA、位序和延时。
- 依赖 CPU 逐位翻转 GPIO，速度和效率低于硬件 SPI。
- 程序执行时间容易受中断影响，不适合严格的高速实时通信。

#### 面试易问

**Q：软件 SPI 和硬件 SPI 有什么区别？**

A：软件 SPI 由 CPU 通过 GPIO 指令逐位生成时钟和数据，灵活但占用 CPU、速度较低；硬件 SPI 由片上外设自动完成移位、时钟和标志管理，速度更高、CPU 占用更低，但引脚和配置受外设限制。

**Q：为什么先写软件 SPI，再学习硬件 SPI？**

A：软件 SPI 能清楚展示每个时钟边沿和数据位的关系。理解协议后，硬件 SPI 只是把相同的时序交给外设自动生成，驱动上层的 W25Q64 指令函数通常可以保持不变。

#### 易错点

- 在 W25Q64 驱动层直接写 GPIO，导致代码层次混乱、难以替换为硬件 SPI。
- 把 `CS`、`SCK`、`MOSI`、`MISO` 的方向配置反。
- 复制硬件 SPI 的引脚配置方式，把软件控制的引脚误配成复用功能。
- 高频中断打断位操作，造成时钟周期不均匀或一帧指令被拉长。

---

### 2. SPI 模式 0 的时钟与采样

#### 原理

SPI 模式由 `CPOL` 和 `CPHA` 决定。本实验使用模式 0：

```text
CPOL = 0：SCK 空闲时为低电平
CPHA = 0：第一个边沿采样，第二个边沿切换/准备下一位
```

软件实现顺序可概括为：

```text
先放置 MOSI 数据
→ SCK 拉高，产生上升沿并采样
→ 读取 MISO
→ SCK 拉低，产生下降沿并准备下一位
```

W25Q64 标准 SPI 支持模式 0 和模式 3。课程选择模式 0，逻辑更直观。

#### 特点

- 时钟空闲电平为低。
- 数据必须在上升沿到来前稳定。
- 主机在上升沿附近读取 MISO。
- 每个字节传输需要 8 个完整时钟周期。
- `CS` 拉低和拉高时，SCK 都应处于正确空闲状态。

#### 面试易问

**Q：CPOL 和 CPHA 分别决定什么？**

A：CPOL 决定时钟空闲电平；CPHA 决定数据在第一个边沿还是第二个边沿采样。主机和从机必须使用兼容的模式。

**Q：模式不匹配会出现什么现象？**

A：常见现象是 ID 每次读取值不固定、所有位整体错位、始终读取 `0x00/0xFF`，或低速偶尔正确但提高速度后失败。

#### 易错点

- 初始化后没有把 SCK 置为低电平。
- 在 SCK 上升之后才修改 MOSI，导致从机采到旧数据。
- 读取 MISO 的边沿与从机输出更新边沿冲突。
- 一帧结束后 SCK 停在高电平，下一次片选产生错误的第一个边沿。

---

### 3. SPI 的全双工交换机制

#### 原理

SPI 的发送和接收同时发生。主机每产生一个时钟：

- MOSI 向从机移入一位。
- MISO 向主机移出一位。

所以“只读”也必须发送某个字节来产生时钟；“只写”时也会收到一个字节，只是该返回值通常没有意义。

`MySPI_SwapByte()` 的抽象非常重要：

```text
输入：本次要发送的 8 位数据
输出：同一组 8 个时钟期间接收到的 8 位数据
```

#### 特点

- SPI 没有独立的读时钟，时钟由主机发起。
- 读取阶段常发送 `0xFF` 或 `0x00` 作为 Dummy Byte。
- 写指令时函数返回值通常被忽略。
- 连续读取时只需保持 CS 为低并重复交换字节。
- 同一个底层交换函数可服务于多个不同 SPI 从机。

#### 面试易问

**Q：为什么读取 W25Q64 时还要发送 `0xFF`？**

A：因为 SPI 只有在主机产生时钟时数据才会移位。发送 `0xFF` 的主要目的是产生 8 个时钟，让从机把一个字节从 MISO 移出；MOSI 上的占位值通常不参与当前读操作。

**Q：SPI 为什么称为全双工？**

A：MOSI 和 MISO 是独立数据线，每个时钟周期主从双方都可以同时发送和接收一位数据。

#### 易错点

- 写“接收函数”却不翻转 SCK，结果永远读不到新数据。
- 读取多个字节时每个字节都重新拉高 CS，导致从机重新解释为新指令。
- 误认为发送 `0xFF` 会把 Flash 数据改成 `0xFF`；读取指令期间 MOSI 只是占位数据。
- 接收变量没有初始化为 0，使用按位或后残留旧位。

---

### 4. 指令码、24 位地址与事务边界

#### 原理

W25Q64 的标准操作通常采用以下事务格式：

```text
CS 拉低
→ 发送 1 字节指令码
→ 可选：发送 3 字节地址
→ 可选：发送/接收若干数据
→ CS 拉高
```

常用指令如下：

| 操作 | 指令码 | 后续字段 |
|---|---:|---|
| 写使能 | `0x06` | 无 |
| 读状态寄存器 1 | `0x05` | 连续读状态字节 |
| 页编程 | `0x02` | 24 位地址 + 1～256 字节数据 |
| 4 KB 扇区擦除 | `0x20` | 24 位地址 |
| 普通读取 | `0x03` | 24 位地址 + 连续读取数据 |
| JEDEC ID | `0x9F` | 连续读取 3 个 ID 字节 |

W25Q64 容量为 8 MB，需要 23 位即可覆盖全部地址，但标准指令仍使用 24 位地址字段，因此程序使用 `uint32_t` 保存地址，再发送低 24 位。

#### 特点

- 地址必须高字节先发送。
- 整条指令期间 CS 必须持续为低。
- CS 拉高不仅表示结束，还可能触发芯片开始内部擦写。
- 不同指令需要的地址、Dummy Clock 和数据长度不同。
- 指令码应集中放在单独头文件中，避免散落的“魔法数字”。

#### 面试易问

**Q：为什么地址变量用 `uint32_t`，但只发送三个字节？**

A：C 语言没有常用的 24 位整数类型，使用 `uint32_t` 最方便。W25Q64 标准地址字段为 24 位，所以只发送 `Address >> 16`、`Address >> 8` 和 `Address` 的低 8 位。

**Q：CS 为什么不能每个字节都拉高一次？**

A：从机通过 CS 识别一条完整事务。若指令码后立即拉高 CS，后续地址和数据会被当成新的指令，原事务无法完成。

#### 易错点

- 地址按低字节到高字节发送，导致访问位置完全错误。
- 忘记将右移结果转换为 8 位，虽然函数参数会截断，但代码含义不清晰。
- 页编程数据尚未发送完就拉高 CS。
- 指令码写错，例如把 `0x03` 与 `0x02` 混淆。

---

### 5. 写使能、WEL 与 BUSY 状态

#### 原理

W25Q64 为避免误写，擦除和编程前必须先执行写使能：

```text
发送 0x06
→ 状态寄存器 WEL = 1
→ 执行擦除或编程
→ 操作完成后 WEL 自动清零
```

擦除或编程开始后，芯片进入内部自定时操作，状态寄存器 1 的 `BUSY` 位为 1。此时不能立即发起普通读写，需要轮询：

```text
发送 0x05
→ 不断读取状态字节
→ 检查 bit0
→ bit0 = 0 后结束等待
```

#### 特点

- 每次擦除或页编程前都要重新写使能。
- `BUSY=1` 表示芯片内部仍在执行擦写。
- 读状态寄存器可在擦写期间执行。
- 写使能与等待忙是两个不同阶段，不能互相替代。
- 实际工程必须设计超时和错误返回机制。

#### 面试易问

**Q：为什么执行一次写使能后，不能永久写入？**

A：WEL 是保护性锁存位。大多数写入或擦除操作完成后芯片会自动清零 WEL，降低程序跑飞或噪声造成连续误写的风险。

**Q：为什么不直接使用固定延时等待擦除完成？**

A：擦写时间会随器件、温度、电压和操作类型变化。读取 BUSY 位能在操作真正完成时立即继续，既可靠又避免过长的固定等待。

#### 易错点

- 只在初始化时调用一次写使能，第二次擦写失败。
- 页编程完成后立即读取，没有等待 BUSY 清零。
- `while` 条件没有与 `0x01` 做掩码，误把其他状态位当成忙状态。
- 没有超时机制，接线错误时程序永久卡死。

---

### 6. NOR Flash 的擦除与编程规则

#### 原理

NOR Flash 的基本物理特性是：

```text
擦除：把一个擦除单元中的所有位恢复为 1
编程：只能把位从 1 写成 0
```

因此，擦除后的字节通常为 `0xFF`。若旧数据某一位已经是 0，页编程不能直接把它改回 1，必须先擦除所在扇区。

例如：

```text
旧值：1111 0000 = 0xF0
想写：1111 1111 = 0xFF
```

其中低四位需要从 0 变为 1，单纯页编程无法完成，必须先擦除。

#### 特点

- 最小常用擦除单位为 4 KB 扇区。
- 最小编程数据可为 1 字节。
- 擦除比读取和发送指令慢得多。
- 频繁更新少量参数时，需要设计缓存和磨损均衡。
- 重写数据通常采用“读出扇区 → 修改 RAM 缓冲 → 擦除 → 整扇区写回”。

#### 面试易问

**Q：为什么写 Flash 前通常要先擦除？**

A：NOR Flash 编程只能把位从 1 改成 0，不能把 0 直接改回 1。擦除会把整个扇区恢复成全 1，为后续编程提供条件。

**Q：擦除一个地址为什么会影响周围数据？**

A：擦除不是按字节执行，而是按扇区或块执行。使用 `0x20` 时，地址所在的整个 4 KB 扇区都会变成 `0xFF`。

#### 易错点

- 以为页编程可以像 RAM 赋值一样任意覆盖。
- 为修改一个字节直接擦除扇区，却没有备份同扇区其他有效数据。
- 每次更新参数都擦除同一扇区，造成局部磨损。
- 把“写入 `0xFF`”误当作擦除操作。

---

### 7. 页编程边界与地址回卷

#### 原理

W25Q64 的页大小为 256 字节。页编程指令最多接收 256 个数据字节，并且地址低 8 位代表页内偏移。

若从页中间开始写入，剩余空间小于 256 字节。例如：

```text
起始地址：0x0000F0
页内偏移：0xF0 = 240
本页剩余：256 - 240 = 16 字节
```

若继续发送超过 16 字节，芯片可能将地址回卷到该页开头，覆盖同一页前面的数据，而不会自动进入下一页。

跨页写入应由上层拆分：

```text
先写完当前页剩余空间
→ 地址移动到下一页
→ 再写下一段
```

#### 特点

- 一页为 256 字节。
- `Count <= 256` 并不代表一定不会跨页。
- 必须同时检查 `页内偏移 + Count <= 256`。
- 连续读数据通常没有相同的页边界限制。
- 通用写函数应自动计算分段长度。

#### 面试易问

**Q：从地址 `0x0000F0` 开始最多安全写多少字节？**

A：该地址页内偏移为 240，因此当前页只剩 16 字节。若不做分段，最多安全写 16 字节。

**Q：如何实现任意长度写入？**

A：循环计算当前地址到页尾的剩余空间，每次页编程写入两者中的较小值：`剩余总长度` 与 `当前页剩余长度`，写完后更新地址和数据指针。

#### 易错点

- 只限制 `Count` 不超过 256，却不检查起始地址偏移。
- 误以为芯片会自动跨到下一页。
- 数组看似写入成功，但页首数据被悄悄覆盖。
- 擦除范围和写入范围不匹配，跨扇区后后半部分未擦除。

### 8. JEDEC ID 与分阶段调试

#### 原理

读取 JEDEC ID 是验证 SPI 底层是否正常的首选方法：

```text
CS 拉低
→ 发送 0x9F
→ 接收厂商 ID
→ 接收 Memory Type
→ 接收 Capacity
→ CS 拉高
```

对于常见 Winbond W25Q64，典型结果为：

```text
MID = 0xEF
DID = 0x4017
```

其中：

- `0xEF`：Winbond 厂商 ID。
- `0x40`：存储类型编码。
- `0x17`：容量编码，对应 64 Mbit 等级。

先读 ID，再测试擦写，可以把问题分成两类：

1. ID 错误：优先检查接线和 SPI 时序。
2. ID 正确但写入失败：优先检查写使能、BUSY、写保护、擦除和页边界。

#### 特点

- 读 ID 不会修改 Flash 内容，适合反复测试。
- ID 是固定已知值，便于判断位序和字节顺序。
- 全 `0xFF` 常见于 MISO 上拉、从机未选中或未连接。
- 全 `0x00` 常见于 MISO 短路到地、供电异常或读时序错误。
- 克隆器件或不同型号的 ID 可能与 Winbond 原厂值不同。

#### 面试易问

**Q：为什么驱动调试时先读 ID？**

A：读 ID 只涉及最基础的“发送指令并连续接收”，不会受到擦除、写保护和页边界影响。ID 正确说明供电、片选、时钟、位序和 MISO/MOSI 大概率已经正常。

**Q：读到 `0xFFFFFF` 通常说明什么？**

A：通常表示 MISO 始终为高电平，可能是从机没有被 CS 选中、MISO 未连接、模块未供电、引脚配置错误或线路被上拉但从机未输出。

#### 易错点

- 将 `MID` 和 `DID` 的字节顺序拼接错误。
- 读取 ID 时少产生一个字节的时钟。
- OLED 显示位数设置错误，导致正确值看起来异常。
- 只根据 ID 判断芯片一定是正品；ID 可以证明协议响应，但不能单独完成真伪鉴定。

## 本节核心记忆

```text
1. 软件 SPI 的本质：用 GPIO 按规定边沿产生时钟并交换数据。

2. 模式 0：
   SCK 空闲低；
   先放 MOSI；
   上升沿采样；
   下降沿准备下一位。

3. SPI 读数据也必须发送 Dummy Byte 来产生时钟。

4. W25Q64 一条典型事务：
   CS↓ → 指令码 → 24 位地址 → 数据 → CS↑

5. 常用指令：
   0x9F 读 JEDEC ID
   0x06 写使能
   0x05 读状态寄存器 1
   0x20 4 KB 扇区擦除
   0x02 页编程
   0x03 普通读取

6. 擦除/编程前必须写使能，完成后必须等待 BUSY 清零。

7. NOR Flash：
   擦除后为 0xFF；
   编程只能 1 → 0；
   0 → 1 必须先擦除。

8. 页大小 256 字节：
   页编程不能跨页；
   起始偏移 + 长度必须 ≤ 256。

9. 调试顺序：
   先读 ID → 再擦除 → 再写入 → 再读回 → 最后检查边界和保护状态。
```

## 开发过程总结

### 问题 1：OLED 显示的 ID 为 `FFFF`、`0000` 或每次变化

现象：

- `MID` 和 `DID` 不是预期值。
- 读到全 `0xFF` 或全 `0x00`。
- 每次复位后 ID 不一致。
- 降低速度后偶尔正确。

排查过程：

1. 检查 W25Q64 是否使用 3.3V 供电，所有模块是否共地。
2. 对照模块丝印确认 `DO` 接 PA6、`DI` 接 PA7，不要把 MISO 与 MOSI 接反。
3. 检查 PA4 是否真正拉低，逻辑分析仪上 CS 应覆盖完整的 `9F + 3 字节读取`。
4. 检查 SCK 空闲是否为低，是否严格执行“先输出 MOSI、再上升沿采样”。
5. 检查 MISO 是否被误配置为输出。
6. 使用逻辑分析仪解码 SPI 模式 0、MSB First，确认主机是否发送 `0x9F`。

解决方案：

- 修正接线和 GPIO 方向。
- 初始化后明确设置 `CS=1`、`SCK=0`。
- 确保 `MySPI_SwapByte()` 先放数据再产生上升沿。
- 裸芯片将 `/WP` 和 `/HOLD` 正确上拉。

### 问题 2：ID 正确，但写入后读回仍为 `FF` 或旧数据

现象：

- `0x9F` 读取 ID 正常。
- 扇区擦除后读回 `FF`，但页编程后数据没有变化。
- 断电重启后问题仍然存在。

排查过程：

1. 确认每次页编程前是否调用 `W25Q64_WriteEnable()`。
2. 读取状态寄存器，确认发送 `0x06` 后 WEL 是否置位。
3. 确认页编程结束后是否拉高 CS，并等待 BUSY 清零。
4. 检查目标区域是否被状态寄存器保护位或单独块锁保护。
5. 确认 `WP` 引脚和状态寄存器保护配置没有阻止写入。
6. 更换一个明确擦除过的地址进行测试。

解决方案：

- 在每次擦除、页编程前重新发送 `0x06`。
- 在每次擦写后轮询 BUSY。
- 若芯片处于写保护状态，依据具体型号数据手册谨慎清除保护位。
- 不要盲目写状态寄存器；先读取并确认原值，避免误改 QE、锁定位或保护范围。

> 江协科技疑难解答中提到过一种典型情况：ID 读取正确，但数据无法写入，原因可能是掉电不丢失的写保护位已被设置。处理时应先核对芯片具体型号和状态寄存器定义，再决定是否清除保护位。

### 问题 3：写入较长数组后，页首数据被覆盖

现象：

- 写入长度小的时候正常。
- 从接近页尾的地址开始写入较长数组后，读回顺序异常。
- 当前页开头的数据被本次写入的后半段覆盖。

排查过程：

1. 计算起始地址低 8 位，即页内偏移。
2. 计算当前页剩余空间：`256 - (Address & 0xFF)`。
3. 检查 `Count` 是否超过当前页剩余空间。
4. 检查上层写函数是否错误地认为“Count 不超过 256 就一定安全”。
5. 使用逻辑分析仪确认一条 `0x02` 指令后发送了多少数据字节。

解决方案：

- 禁止单次页编程跨页。
- 通用写函数按页拆分数据。
- 每次只写 `min(剩余长度, 当前页剩余空间)`。
- 若写入跨越扇区，还要确认目标扇区均已正确擦除。

### 问题 4：程序卡在 `W25Q64_WaitBusy()`

现象：

- OLED 初始化后无后续显示。
- 调试器显示程序长期停留在 BUSY 轮询。
- 逻辑分析仪上不断重复读取状态寄存器。

排查过程：

1. 检查是否成功发送了 `0x05`，且 CS 在连续轮询期间保持低电平。
2. 检查 MISO 是否一直被读取为 1。
3. 检查器件供电是否稳定，写入过程中是否掉电或电压过低。
4. 检查前一条擦除/编程指令格式是否完整，CS 是否正确拉高触发执行。
5. 检查超时计数是否合理，以及超时后是否有错误提示。
6. 检查芯片是否型号不匹配、损坏或处于异常保护状态。

解决方案：

- 为等待函数加入超时和返回值。
- 超时时显示错误码或通过串口输出状态寄存器值。
- 将“等待成功”和“等待超时”传递给上层，不要在失败后继续读写。
- 量产代码应加入复位 Flash、重新初始化总线或故障降级机制。

### 问题 5：擦除一个地址后，附近大量数据都消失

现象：

- 只想修改一个字节，却发现同一片区域的其他参数也变成 `FF`。
- 擦除函数看似地址正确，但影响范围远大于一个字节。

排查过程：

1. 确认使用的是 `0x20` 扇区擦除指令。
2. 计算目标地址所属扇区：`SectorBase = Address & 0xFFF000`。
3. 检查是否把多个独立参数放在同一个 4 KB 扇区。
4. 擦除前读取并备份整个扇区。
5. 检查回写时是否把未修改的数据一并恢复。

解决方案：

- 设计 4 KB RAM 缓冲区：读出整扇区、修改目标字节、擦除、整扇区写回。
- 将频繁更新和只读数据分配到不同扇区。
- 对重要参数使用双备份、版本号和校验值。
- 需要高频小数据更新时，考虑 EEPROM、FRAM 或日志式存储方案。

## 结果展示

> 实验 1：上电后成功读取 JEDEC ID；使用 Winbond W25Q64 时，OLED 常见显示 `MID: EF`、`DID: 4017`。✅

> 实验 2：擦除首个 4 KB 扇区后，目标区域读回值为 `FF`。✅

> 实验 3：向地址 `0x000000` 写入 `01 02 03 04`，随后从相同地址读回的数据与写入数组一致。✅

> 实验 4：OLED 第二行显示写入数组 `01 02 03 04`，第三行显示读回数组 `01 02 03 04`，完成端到端验证。✅

> 实验 5：使用逻辑分析仪观察时，可看到 `CS↓ → 02/20/03/9F 指令 → 地址/数据 → CS↑` 的完整事务结构。✅

## 本节小结

本节通过 GPIO 模拟 SPI，完成了 W25Q64 的读取 ID、写使能、忙状态检测、扇区擦除、页编程和连续读取。

需要真正掌握的不是某一份固定代码，而是以下三条主线：

1. **协议主线**：理解模式 0 的边沿、全双工交换和 CS 事务边界。
2. **器件主线**：理解 W25Q64 的指令码、24 位地址、页/扇区组织和 NOR Flash 擦写特性。
3. **软件主线**：使用 GPIO 层、SPI 层、器件层和应用层分层封装，使后续替换为硬件 SPI 时只需修改底层交换函数。

进入硬件 SPI 章节后，`W25Q64.c` 中的上层指令流程基本可以保持不变，只需将 `MySPI_SwapByte()` 从 GPIO 位操作替换为 STM32 SPI 外设的数据寄存器收发。这正是分层驱动设计的价值。
