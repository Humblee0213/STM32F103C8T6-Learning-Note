## 实验概述

本节围绕 STM32F103C8T6 的内部 Flash 存储资源，完成两个核心实验：

1. 读取芯片相关标识信息，例如 Flash 容量、唯一设备标识符和设备 ID。
2. 对内部 Flash 某个预留页面执行解锁、擦除、半字写入和数据读取，实现简单的掉电保存。

本节的核心目标是理解：

```text
内部 Flash 不只是拿来存程序，也可以在应用运行时保存少量长期数据
```

但要注意，Flash 不是 RAM。它的写入流程更严格，写之前通常要先擦除，写入粒度、擦除粒度、寿命次数和访问时序都有明确约束。

## 硬件连接

本节实验主要依赖芯片内部 Flash 和调试信息寄存器，外部硬件主要用于观察读写结果。

|---|---:|---|

## 核心代码

### 1. 头文件与地址定义

```c
#ifndef __MYFLASH_H                                                                    // 判断是否尚未定义 __MYFLASH_H，防止头文件被重复包含
#define __MYFLASH_H                                                                    // 定义 __MYFLASH_H 宏，配合条件编译实现头文件保护

#include "stm32f10x.h"                                                                 // 引入 STM32F10x 标准外设库主头文件，提供 FLASH 和 DBGMCU 相关类型与函数

#define FLASH_STORE_ADDR      0x0800FC00                                               // 定义示例数据存储页首地址，适用于预留最后一页的典型 64KB 布局，实际使用前需确认工程未占用该页
#define FLASH_SIZE_ADDR       0x1FFFF7E0                                               // 定义 Flash 容量信息地址，该地址存放芯片容量信息
#define UNIQUE_ID_ADDR0       0x1FFFF7E8                                               // 定义唯一设备标识第 1 个 32 位字的地址
#define UNIQUE_ID_ADDR1       0x1FFFF7EC                                               // 定义唯一设备标识第 2 个 32 位字的地址
#define UNIQUE_ID_ADDR2       0x1FFFF7F0                                               // 定义唯一设备标识第 3 个 32 位字的地址

void MyFLASH_WriteHalfWord(uint32_t Address, uint16_t Data);                           // 声明单个半字写入函数，用于向指定 Flash 地址写入 16 位数据
uint16_t MyFLASH_ReadHalfWord(uint32_t Address);                                       // 声明单个半字读取函数，用于从指定 Flash 地址读回 16 位数据
void MyFLASH_WritePage(uint32_t Address, uint16_t *DataArray, uint16_t Count);         // 声明整页写入函数，用于擦除目标页后批量写入半字数组
void MyFLASH_ReadPage(uint32_t Address, uint16_t *DataArray, uint16_t Count);          // 声明批量读取函数，用于从指定页连续读回多个半字
uint16_t MyFLASH_GetFlashSize(void);                                                   // 声明 Flash 容量读取函数，用于获取芯片标称容量
uint32_t MyFLASH_GetUniqueID(uint8_t Index);                                           // 声明唯一 ID 读取函数，用于读取 96 位唯一标识中的某一段

#endif                                                                                 // 结束头文件保护条件编译
```

### 2. Flash 写入与读取

```c
#include "MyFlash.h"                                                                   // 引入自定义 Flash 头文件，使用其中的地址宏和函数声明

void MyFLASH_WriteHalfWord(uint32_t Address, uint16_t Data)                             // 定义半字写入函数，内部 Flash 在 STM32F1 中常用半字粒度编程
{                                                                                       // 函数体开始，下面执行解锁、写入、等待完成和上锁流程
    FLASH_Unlock();                                                                     // 解锁 Flash 控制器，否则程序无法执行擦除或写入操作
    FLASH_ClearFlag(FLASH_FLAG_EOP | FLASH_FLAG_PGERR | FLASH_FLAG_WRPRTERR);          // 清除完成标志和潜在错误标志，避免上一次操作状态影响当前写入
    FLASH_ProgramHalfWord(Address, Data);                                               // 向目标地址编程一个 16 位半字数据
    FLASH_Lock();                                                                       // 写入完成后重新上锁，避免后续代码误操作 Flash
}                                                                                       // 半字写入函数结束

uint16_t MyFLASH_ReadHalfWord(uint32_t Address)                                         // 定义半字读取函数，直接按存储器地址读取 Flash 内容
{                                                                                       // 函数体开始，下面通过指针解引用返回 16 位数据
    return *(__IO uint16_t *)Address;                                                   // 把目标地址强制转换为 16 位易失性指针并读取，确保每次都访问真实存储单元
}                                                                                       // 半字读取函数结束

void MyFLASH_WritePage(uint32_t Address, uint16_t *DataArray, uint16_t Count)           // 定义整页写入函数，适合一次保存多个参数
{                                                                                       // 函数体开始，下面先解锁并擦除整页，再逐个写入半字数据
    uint16_t i;                                                                         // 定义循环变量，用于遍历待写入的数据数组

    FLASH_Unlock();                                                                     // 解锁 Flash 控制器，允许后续擦除和写入操作
    FLASH_ClearFlag(FLASH_FLAG_EOP | FLASH_FLAG_PGERR | FLASH_FLAG_WRPRTERR);          // 清除完成和错误标志，保证本次编程流程在干净状态下开始
    FLASH_ErasePage(Address);                                                           // 擦除目标页，因为 Flash 不能像 RAM 一样直接覆盖写入

    for (i = 0; i < Count; i++)                                                         // 遍历待写入数组中的每个半字，逐项写入 Flash 页面
    {                                                                                   // for 循环体开始，下面根据半字偏移量依次写入
        FLASH_ProgramHalfWord(Address + i * 2, DataArray[i]);                           // 每次向当前地址写入一个半字，地址步进 2 字节
    }                                                                                   // for 循环体结束，当前页的所有目标数据已经写入完成

    FLASH_Lock();                                                                       // 页写入完成后重新上锁，防止其他代码误修改 Flash
}                                                                                       // 整页写入函数结束

void MyFLASH_ReadPage(uint32_t Address, uint16_t *DataArray, uint16_t Count)            // 定义批量读取函数，用于从 Flash 页中读取多个半字数据
{                                                                                       // 函数体开始，下面逐项按地址读取并存入 RAM 数组
    uint16_t i;                                                                         // 定义循环变量，用于遍历读取数量

    for (i = 0; i < Count; i++)                                                         // 遍历需要读取的每个半字位置
    {                                                                                   // for 循环体开始，下面按顺序读取 Flash 页面内容
        DataArray[i] = MyFLASH_ReadHalfWord(Address + i * 2);                           // 从当前半字地址读取数据，并保存到 RAM 数组中
    }                                                                                   // for 循环体结束，当前索引的数据已经读回
}                                                                                       // 批量读取函数结束
```

### 3. 读取 Flash 容量与芯片唯一 ID

```c
#include "MyFlash.h"                                                                   // 引入自定义 Flash 头文件，使用容量地址和唯一 ID 地址宏

uint16_t MyFLASH_GetFlashSize(void)                                                     // 定义 Flash 容量读取函数，返回单位通常为 KB
{                                                                                       // 函数体开始，下面直接从系统存储区固定地址读取容量值
    return *(__IO uint16_t *)FLASH_SIZE_ADDR;                                           // 把容量地址转成 16 位易失性指针并读取，得到芯片的标称 Flash 容量
}                                                                                       // Flash 容量读取函数结束

uint32_t MyFLASH_GetUniqueID(uint8_t Index)                                             // 定义唯一设备标识读取函数，参数 Index 指明读取哪一个 32 位字
{                                                                                       // 函数体开始，下面按索引选择对应的唯一 ID 地址
    if (Index == 0)                                                                     // 判断是否需要读取第 1 段唯一 ID
    {                                                                                   // 第 1 段分支开始，返回最低地址处的 32 位标识
        return *(__IO uint32_t *)UNIQUE_ID_ADDR0;                                       // 读取唯一 ID 第 1 个 32 位字并返回
    }                                                                                   // 第 1 段分支结束
    else if (Index == 1)                                                                // 判断是否需要读取第 2 段唯一 ID
    {                                                                                   // 第 2 段分支开始，返回中间地址处的 32 位标识
        return *(__IO uint32_t *)UNIQUE_ID_ADDR1;                                       // 读取唯一 ID 第 2 个 32 位字并返回
    }                                                                                   // 第 2 段分支结束
    else                                                                                // 如果不是前两个索引，则按第 3 段处理
    {                                                                                   // 第 3 段分支开始，返回最高地址处的 32 位标识
        return *(__IO uint32_t *)UNIQUE_ID_ADDR2;                                       // 读取唯一 ID 第 3 个 32 位字并返回
    }                                                                                   // 第 3 段分支结束
}                                                                                       // 唯一设备标识读取函数结束
```

### 4. 主函数测试框架

```c
#include "stm32f10x.h"                                                                 // 引入 STM32F10x 标准外设库主头文件，提供芯片外设定义
#include "OLED.h"                                                                      // 引入 OLED 显示驱动，用于显示写入值、读回值和芯片信息
#include "MyFlash.h"                                                                   // 引入自定义 Flash 操作头文件，使用写读接口和地址宏

uint16_t WriteData[4] = {0x1234, 0x5678, 0x9ABC, 0xDEF0};                               // 定义待写入 Flash 的测试数组，用于验证页写入和页读取流程
uint16_t ReadData[4];                                                                   // 定义读回数组，用于保存从 Flash 页中读取出的半字数据

int main(void)                                                                          // 主函数入口，芯片复位后从这里开始执行
{                                                                                       // 主函数体开始，下面先初始化显示，再执行写入和读取实验
    uint8_t i;                                                                          // 定义循环变量，用于遍历显示读回数组

    OLED_Init();                                                                        // 初始化 OLED，方便直观看到 Flash 存储和芯片 ID 的读取结果
    MyFLASH_WritePage(FLASH_STORE_ADDR, WriteData, 4);                                  // 把测试数组写入预留 Flash 页，函数内部会先擦除再逐个半字编程
    MyFLASH_ReadPage(FLASH_STORE_ADDR, ReadData, 4);                                    // 从同一 Flash 页把刚写入的数据读回到 RAM 数组中

    OLED_ShowString(1, 1, "Size:");                                                     // 在 OLED 第 1 行显示容量标签，提示后面是 Flash 容量
    OLED_ShowNum(1, 6, MyFLASH_GetFlashSize(), 3);                                      // 显示芯片的标称 Flash 容量，单位通常为 KB

    for (i = 0; i < 4; i++)                                                             // 遍历读回数组，逐项显示写回来的数据是否正确
    {                                                                                   // for 循环体开始，下面把每个半字显示成十六进制数
        OLED_ShowHexNum(2 + i / 2, 1 + (i % 2) * 8, ReadData[i], 4);                    // 在 OLED 第 2、3 行按两列显示读回的 4 个半字
    }                                                                                   // for 循环体结束，所有测试数据都已经显示到 OLED 上

    while (1)                                                                           // 进入主循环，保持显示结果，便于观察和调试
    {                                                                                   // 主循环体开始，本实验核心流程已完成，因此此处保持空转即可
    }                                                                                   // 主循环体结束，程序会持续停留在显示状态
}                                                                                       // 主函数结束，嵌入式程序一般不会执行到这里
```

## 代码要点

| 行/段 | 说明 |
|---|---|
| `FLASH_Unlock()` / `FLASH_Lock()` | 写或擦除 Flash 前必须先解锁，完成后建议重新上锁，降低误写风险。 |
| `FLASH_ErasePage()` | STM32F1 内部 Flash 不能像 RAM 一样直接覆盖写，整页写新数据前通常要先擦除目标页。 |
| `FLASH_ProgramHalfWord()` | 中密度 STM32F1 常见的编程粒度是半字 `16 bit`，地址也要保持半字对齐。 |
| `FLASH_ClearFlag()` | 清除上一次完成和错误状态，避免编程错误标志残留影响本次操作。 |
| `FLASH_STORE_ADDR` | 必须指向预留页，绝不能写到当前程序代码所在页，否则轻则程序异常，重则整段代码被破坏。 |
| `FLASH_SIZE_ADDR` | 系统存储区中的容量信息地址，可用于判断芯片标称 Flash 大小。 |
| `UNIQUE_ID_ADDR0~2` | 96 位唯一设备标识通常分 3 个 `32 bit` 读取，常用于设备追踪、序列号或授权绑定。 |
| `ReadData` 回读数组 | 先写再读是最基本的 Flash 实验闭环，能快速验证地址、擦除和编程流程是否正确。 |

## 关键知识点

### 1. 内部 Flash 的读写特性

#### 原理

STM32 的内部 Flash 是非易失性存储器，掉电后数据不会丢失。它最主要的用途是存放程序代码，但也可以在应用运行时保存少量参数、配置或标志位。

和 RAM 最大的区别是：Flash 读取像普通存储器一样方便，但写入必须遵守专门的编程流程，而且通常不能直接把任意位从 `0` 改回 `1`，因此很多情况下必须先擦除整页。

#### 特点

- 掉电不丢失，适合保存长期参数。
- 读取简单，按地址即可访问。
- 写入前通常要先擦除目标页。
- 擦除粒度通常是“页”，不是单个字节。
- 写入寿命有限，不适合高频日志型写入。

#### 面试易问

**Q：为什么 Flash 写入前通常要先擦除？**

A：因为 Flash 单元的物理特性决定了很多位只能从 `1` 编程成 `0`，不能像 RAM 那样任意覆盖。如果想把原来已经写过的位恢复到 `1`，通常必须执行页擦除。

**Q：内部 Flash 和 EEPROM 的使用思路有什么区别？**

A：内部 Flash 容量大、普遍可用，但擦除按页进行、写入寿命有限；EEPROM 更适合少量频繁参数更新。STM32F1 没有真正独立 EEPROM，所以常用 Flash 模拟参数存储。

#### 易错点

- 把 Flash 当 RAM 一样直接覆盖写。
- 没有擦除就反复写，结果读回数据异常。
- 高频保存计数或日志，导致寿命消耗过快。
- 没有做写后校验，现场难以确认是否成功写入。

---

### 2. 页擦除与半字编程

#### 原理

STM32F1 内部 Flash 常见编程流程是：

```text
解锁 → 清标志 → 擦除页 → 半字写入 → 上锁
```

中密度 F1 系列常用半字编程，也就是一次写入 `16 bit` 数据。页擦除会把整个页恢复为擦除态，因此如果只想修改一小部分数据，实际项目里常要先把整页读到 RAM、修改后再整页回写。

#### 特点

- 擦除粒度大于写入粒度。
- 编程粒度常为半字。
- 地址需要对齐，流程必须严格。
- 单次保存少量参数很方便，但复杂结构需要页管理策略。

#### 面试易问

**Q：为什么写一个参数有时也要操作整页？**

A：因为擦除通常按页进行。如果一个页面里还放着其他有效参数，单独更新其中一项时，往往要先把整页内容搬到 RAM，修改目标项，再把整页重新擦除并写回。

**Q：半字编程是什么意思？**

A：在 STM32F1 常见 Flash 编程模式下，一次写入的基本单位是半字，也就是 `16 bit`。因此地址应按 2 字节对齐，数据也按半字组织更稳妥。

#### 易错点

- 写地址没有半字对齐。
- 忘记解锁就直接调用编程函数。
- 只想写少量数据，却不考虑页内其他数据会被擦掉。
- 没有在写完后重新上锁。

---

### 3. 预留测试页的选择

#### 原理

内部 Flash 同时存放程序代码和用户数据，所以写测试页时必须避开程序映像所在区域。最常见的做法是预留最后一页或若干页专门作为参数区，并在链接脚本或工程约定中明确保留。

如果页地址选错，擦除操作可能直接把程序代码抹掉。

#### 特点

- 数据页必须与代码页隔离。
- 示例地址不能脱离实际工程直接照搬。
- 芯片容量不同，最后一页地址也不同。
- 工程变大后，原本安全的页地址也可能不再安全。

#### 面试易问

**Q：为什么示例里常把参数区放在最后一页？**

A：因为最后一页通常最容易集中管理，也便于和程序代码区隔离。但这不是绝对规则，前提是你确认链接后的程序不会占用到那一页。

**Q：如何确认 Flash 测试页不会覆盖程序？**

A：可以查看芯片容量、链接脚本、Map 文件和最终程序大小，确保所选页面完全在代码区之外，并最好把这段区域显式规划成参数区。

#### 易错点

- 没看 Map 文件就随手选地址。
- 工程后期代码变大，侵占了原先预留页却没有更新地址。
- 不同芯片容量共用同一个硬编码地址，导致兼容性问题。
- 调试阶段写了程序页，误以为是“代码不稳定”。

---

### 4. 芯片 ID 与唯一设备标识

#### 原理

STM32 芯片内部通常提供几类“身份信息”：

- 设备 ID / 修订版本 ID：用于区分芯片型号和修订版本。
- Flash 容量信息：用于读取芯片标称 Flash 大小。
- 96 位唯一设备标识：每颗芯片不同，可视为硬件序列号。

这些信息通常位于固定系统存储区地址，程序可以直接读取。

#### 特点

- 无需擦写，直接读即可。
- 适合做设备标识、序列号、授权绑定或产测追踪。
- Flash 容量信息能帮助程序区分不同存储规模芯片。
- 唯一 ID 通常不适合作为高强度安全密钥本体，但很适合做设备唯一性标识。

#### 面试易问

**Q：唯一设备 ID 有什么实际用途？**

A：常用于设备序列号、生产追踪、授权绑定、通信节点标识、日志回溯等场景，因为每颗芯片的唯一 ID 都不同。

**Q：读取 Flash 容量有什么意义？**

A：它可以让程序知道当前芯片的标称 Flash 大小，从而帮助决定参数页地址、功能裁剪策略，或在兼容多容量芯片时做运行时区分。

#### 易错点

- 把设备 ID、唯一 ID、Flash 容量这几类信息混为一谈。
- 以为唯一 ID 是可改写区域，实际上它通常是固定只读信息。
- 不区分标称容量和实际代码占用空间。
- 直接把唯一 ID 当作绝对安全密钥使用，没有再做派生或保护。

---

### 5. Flash 在面试和项目里的真实价值

#### 原理

内部 Flash 最常见的项目用途不是“存很大数据”，而是保存少量、关键、掉电必须保留的信息，例如：

- 校准参数
- 串口地址
- 启动标志
- 用户配置
- 故障计数

因此，面试里比“会不会调用 `FLASH_ErasePage`”更重要的是你能否讲清楚参数页布局、掉电保护、寿命管理和异常恢复。

#### 特点

- 特别适合少量低频更新参数。
- 需要权衡寿命、容量、写入时机和异常恢复。
- 常与 CRC、版本号、双备份页等机制配合使用。
- 是从实验代码走向工程化参数管理的重要一步。

#### 面试易问

**Q：如果参数经常更新，直接写同一页会有什么问题？**

A：Flash 擦写寿命有限，反复写同一页会加速老化。工程上通常会通过磨损均衡、双页轮换、批量提交或减少写频率来延长寿命。

**Q：如何提高 Flash 参数保存的可靠性？**

A：可以增加数据头、版本号、长度、CRC 校验、双页备份、写后读回校验，以及异常掉电恢复策略，避免只靠一次裸写就认为数据一定安全。

#### 易错点

- 保存频率过高，寿命被迅速耗尽。
- 没有校验字段，读到坏数据也不知道。
- 擦写时发生掉电，没有设计恢复策略。
- 只做实验写通了，就直接用于长期可靠场景。

## 开发过程总结

### 问题 1：写入后读回数据不对

现象：

- 程序执行了写函数。
- OLED 或串口能打印读回值，但和写入值不一致。
- 常见表现是某些位总写不回 `1`。

排查过程：

1. 检查写入前是否执行了页擦除。
2. 检查地址是否按半字对齐。
3. 检查是否确实写到了目标页，而不是读写地址不一致。
4. 检查写完后是否重新从 Flash 地址读回验证。

解决方案：

- 对需要更新的页先做擦除。
- 保证地址和数据粒度与半字编程一致。
- 先做最小闭环实验：写 1 个半字、读 1 个半字，再扩展到数组。

### 问题 2：程序下载后运行异常，甚至直接跑飞

现象：

- 一加入 Flash 擦写代码，程序就不稳定。
- 烧录后有时无法正常显示或直接 HardFault。
- 严重时会发现代码区内容被破坏。

排查过程：

1. 检查 `FLASH_STORE_ADDR` 是否落在程序代码区。
2. 检查当前工程大小是否已经侵占预留页。
3. 检查是否误把中断向量表或关键函数所在页当作测试页擦掉。

解决方案：

- 通过芯片容量、链接脚本和 Map 文件重新确认参数页。
- 把参数页地址写成统一宏定义，集中管理。
- 工程增大后重新校验预留页是否仍安全。

### 问题 3：写入偶尔成功，偶尔失败

现象：

- 同样的代码有时能读回正确数据，有时不行。
- 某些板子正常，某些板子表现异常。
- 常见于边界条件或状态标志没处理干净的情况。

排查过程：

1. 检查写前是否清除了 `EOP`、`PGERR`、`WRPRTERR` 等标志。
2. 检查是否在写保护区域操作。
3. 检查电源是否稳定，调试时是否频繁复位中断流程。
4. 检查是否对返回状态做了判断。

解决方案：

- 写前统一清标志，写后最好检查返回状态或读回校验。
- 避免在供电不稳或反复复位状态下做连续擦写实验。
- 若用于工程，增加失败重试和错误日志。

### 问题 4：读取芯片 ID 后数值看起来“奇怪”

现象：

- 读出的唯一 ID 不是连续自然数。
- 不同板子上显示的数值格式差别很大。
- Flash 容量值和自己印象中的“C8 应该是 64KB”不完全一致。

排查过程：

1. 检查读取的是设备 ID、唯一 ID 还是 Flash 容量。
2. 检查显示格式是否使用了十六进制或十进制混排。
3. 检查芯片实际容量信息是否与板卡标识一致。

解决方案：

- 明确区分“唯一 ID”“设备 ID”“Flash 容量”三类概念。
- 显示 ID 时优先用十六进制，更便于比对。
- 以读到的容量信息和官方资料为准，再结合实际工程验证。

## 结果展示

> 实验 1：程序把测试数组写入预留 Flash 页后，读回数组与写入值一致，说明页擦除和半字编程流程正确。✅

> 实验 2：OLED 或串口能够显示芯片 Flash 容量信息，可用于区分当前芯片的存储规模。✅

> 实验 3：程序可读取 96 位唯一设备标识，并将其作为设备身份信息输出。✅

> 实验 4：复位或掉电后再次上电，Flash 中保存的数据仍然存在，验证了其非易失性特征。✅
