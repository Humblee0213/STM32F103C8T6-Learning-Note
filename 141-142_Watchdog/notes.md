## 实验概述

本节围绕 STM32F103C8T6 的 WDG (Watchdog) 看门狗机制，完成两个核心实验：

1. 使用 IWDG (Independent Watchdog) 独立看门狗，在程序跑飞或长时间卡死时触发系统复位。
2. 使用 WWDG (Window Watchdog) 窗口看门狗，在程序“喂狗过晚”或“喂狗过早”时都触发复位，并可利用 EWI (Early Wakeup Interrupt) 提前中断做保护处理。

本节的核心目标不是记住几个函数名，而是理解：

```text
看门狗的本质 = 用硬件定时器监督软件是否还在按预期运行
```

如果主循环、任务调度或中断系统出现异常，程序没有在规定时间内刷新看门狗计数器，芯片就会自动复位，尽可能把系统拉回可运行状态。

## 硬件连接

本节主要使用芯片内部看门狗外设。为了观察复位和运行状态，通常会配合 OLED、LED 或串口打印。

| 器件 | 对应引脚 | 说明 |
|---|---:|---|
| STM32F103C8T6 | 内部 IWDG / WWDG | 独立看门狗和窗口看门狗均为芯片内部外设 |
| OLED 显示屏 | PB8 / PB9 | 课程常用软件 I2C OLED，用于显示计数值、复位提示或喂狗状态 |
| LED | PA0 | 可用于观察系统是否周期性运行，具体触发电平以开发板原理图为准 |
| 按键 | PA0 / PB1 等 | 可用于手动制造“卡死”或控制是否喂狗，具体按键引脚以现有驱动为准 |
| ST-Link V2 | PA13、PA14、GND、3.3V | SWD 下载与调试 |

> 注意：看门狗实验的现象通常不是“外设动作变多”，而是“系统在异常后是否自动复位并恢复”。如果串口或 OLED 能显示启动标志、运行计数或复位后提示，现象会更直观。

## 核心代码

### 1. 独立看门狗初始化与喂狗

```c
#include "stm32f10x.h"                                                                 // 引入 STM32F10x 标准外设库主头文件，提供 IWDG 相关函数声明

void MyIWDG_Init(uint8_t Prescaler, uint16_t Reload)                                    // 定义独立看门狗初始化函数，参数分别为预分频系数和重装值
{                                                                                       // 函数体开始，下面按“允许写入 → 配预分频 → 配重装值 → 重装计数器 → 使能”的顺序初始化
    IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);                                       // 允许写 IWDG 配置寄存器，否则预分频和重装值不能被修改
    IWDG_SetPrescaler(Prescaler);                                                       // 设置 IWDG 时钟预分频，决定计数器递减速度
    IWDG_SetReload(Reload);                                                             // 设置 IWDG 重装值，决定超时时间上限
    IWDG_ReloadCounter();                                                               // 先把当前计数器重装一次，避免刚初始化就因为旧值过小而复位
    IWDG_Enable();                                                                      // 使能独立看门狗，启用后通常不能再关闭，只能靠复位重新配置
}                                                                                       // 独立看门狗初始化函数结束

void MyIWDG_Feed(void)                                                                  // 定义独立看门狗喂狗函数，用于在程序正常运行时周期性刷新计数器
{                                                                                       // 函数体开始，下面执行一次重装操作即可完成喂狗
    IWDG_ReloadCounter();                                                               // 重装 IWDG 计数器，防止计数减到 0 后触发系统复位
}                                                                                       // 独立看门狗喂狗函数结束
```

### 2. 窗口看门狗初始化

```c
#include "stm32f10x.h"                                                                 // 引入 STM32F10x 标准外设库主头文件，提供 WWDG、RCC、NVIC 等接口

void MyWWDG_Init(uint8_t Counter, uint8_t Window, uint32_t Prescaler)                   // 定义窗口看门狗初始化函数，参数为计数器初值、窗口值和分频系数
{                                                                                       // 函数体开始，下面先开时钟，再配窗口、分频、中断和计数器
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);                                // 开启 WWDG 外设时钟，窗口看门狗挂载在 APB1 总线上

    WWDG_SetPrescaler(Prescaler);                                                       // 设置 WWDG 时钟分频，决定计数器递减节拍
    WWDG_SetWindowValue(Window);                                                        // 设置窗口值，只有计数器小于该值时才允许正常喂狗
    WWDG_EnableIT();                                                                    // 使能提前唤醒中断 EWI，当计数器减到 0x40 时会先进中断
    WWDG_SetCounter(Counter);                                                           // 装载窗口看门狗计数初值，通常为 0x7F
    WWDG_Enable(Counter);                                                               // 使能窗口看门狗，并让计数器开始递减

    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);                                     // 配置中断分组，为后续 WWDG 中断优先级设置提供分组基础
                                                                                        
    NVIC_InitTypeDef NVIC_InitStructure;                                                // 定义 NVIC 初始化结构体，用于配置 WWDG 中断
    NVIC_InitStructure.NVIC_IRQChannel = WWDG_IRQn;                                     // 选择窗口看门狗中断通道
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;                                     // 使能该中断通道
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 2;                           // 设置抢占优先级，数值越小优先级越高
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 2;                                  // 设置响应优先级，用于同组中断排序
    NVIC_Init(&NVIC_InitStructure);                                                     // 把中断参数写入 NVIC，完成 WWDG 中断配置
}                                                                                       // 窗口看门狗初始化函数结束
```

### 3. 窗口看门狗喂狗与提前唤醒中断

```c
#include "stm32f10x.h"                                                                 // 引入 STM32F10x 标准外设库主头文件，提供 WWDG 相关函数声明

void MyWWDG_Feed(uint8_t Counter)                                                        // 定义窗口看门狗喂狗函数，参数为希望重装的计数器值
{                                                                                       // 函数体开始，下面把计数器写回到较高值以延长下一次超时时间
    WWDG_SetCounter(Counter);                                                           // 重装 WWDG 计数器，但必须在合法窗口内执行，否则会触发复位
}                                                                                       // 窗口看门狗喂狗函数结束

void WWDG_IRQHandler(void)                                                               // 定义窗口看门狗中断服务函数，当计数器减到 0x40 时进入该函数
{                                                                                       // 中断服务函数开始，下面通常先清中断标志，再决定是否喂狗
    WWDG_ClearFlag();                                                                   // 清除 WWDG 提前唤醒中断标志，避免重复进入同一中断
    WWDG_SetCounter(0x7F);                                                              // 在提前唤醒中断里把计数器重装到较高值，相当于一次“被中断驱动的喂狗”
}                                                                                       // 窗口看门狗中断服务函数结束
```

    while (1)                                                                           // 进入主循环，嵌入式程序通常长期在循环中执行任务

## 关键知识点

### 1. 看门狗的本质

#### 原理

看门狗本质上是一个独立于主程序的软件监督机制。程序必须在规定时间内刷新计数器，否则硬件认为“软件可能跑飞、死循环、卡死或失去调度能力”，随后触发复位。

它不是为了替代调试，而是为了让系统在现场异常时具备一定自恢复能力。

#### 特点

- 通过硬件计数器监督软件运行状态。
- 程序必须按时“喂狗”，否则会自动复位。
- 适合提升无人值守系统的可靠性。
- 常用于工业控制、仪器仪表、车载电子、远程终端等场景。

#### 面试易问

**Q：为什么嵌入式系统要加看门狗？**

A：因为现场运行时可能出现跑飞、死循环、外设阻塞或异常中断等问题。看门狗可以在程序失去自恢复能力时强制复位，提高系统可靠性。

**Q：看门狗能解决所有软件 Bug 吗？**

A：不能。看门狗更像最后一道保险，只能在系统失去正常推进能力时尝试复位恢复，不能替代对逻辑错误、时序问题和资源泄漏的根本修复。

#### 易错点

- 把看门狗当成“修复 Bug”的手段，而不是容错手段。
- 喂狗位置放得太随意，导致程序即使异常也仍然能喂到狗。
- 只在实验里会用，项目里反而忘了设计看门狗策略。
- 没有配合复位原因记录，导致现场定位困难。

---

### 2. 独立看门狗 IWDG

#### 原理

IWDG (Independent Watchdog) 由内部低速时钟 LSI 驱动，与主时钟树相对独立。即使主时钟异常，只要 LSI 还在运行，IWDG 仍然可以继续倒计时并在超时后复位系统。

这也是它叫“独立”看门狗的原因。

#### 特点

- 使用 LSI 低速内部时钟，独立于主时钟。
- 适合防止程序长时间卡死或跑飞。
- 一旦启动，通常不能软件关闭。
- 可靠性高，适合作为系统最后一道复位保护。

#### 面试易问

**Q：IWDG 为什么比普通软件定时器更可靠？**

A：因为 IWDG 由独立的 LSI 驱动，不依赖主程序调度和主时钟树。即使主时钟异常或任务系统失效，只要 LSI 正常，它仍能继续倒计时并复位系统。

**Q：IWDG 超时时间怎么估算？**

A：通常按 `Tout = Reload * Prescaler / LSI_Freq` 近似估算。由于 LSI 本身精度有限，实际超时时间会有一定偏差，所以工程里要留安全裕量。

#### 易错点

- 忘记 LSI 频率有误差，导致超时时间和理论值不完全一致。
- IWDG 启动后还以为能像普通外设一样随时关闭。
- 喂狗过于频繁地放在中断中，导致主循环卡死时仍然不复位。
- 选了过短的超时时间，正常任务偶尔阻塞也会误复位。

---

### 3. 窗口看门狗 WWDG

#### 原理

WWDG (Window Watchdog) 由 APB1 时钟分频得到计数时钟，计数器会从较高值递减到 `0x40`。程序只有在计数器低于窗口值且高于 `0x40` 的合法区间内，才允许重新装载计数器。

如果喂狗过早，说明程序可能异常高速循环；如果喂狗过晚，说明程序可能被阻塞太久。两种情况都能触发复位，这就是窗口看门狗比独立看门狗更严格的地方。

#### 特点

- 依赖 APB1 时钟，不如 IWDG 那样完全独立。
- 能同时检测“过晚喂狗”和“过早喂狗”。
- 支持提前唤醒中断 EWI，可在真正复位前先进入一次中断。
- 适合对任务节拍、执行窗口有更严格要求的系统。

#### 面试易问

**Q：WWDG 为什么能检测喂狗过早？**

A：因为它设置了窗口值，只有计数器递减到窗口以下时才能合法喂狗。如果程序在计数还很高时就刷新，硬件会认为执行节拍异常，从而触发复位。

**Q：IWDG 和 WWDG 该怎么选？**

A：如果更强调独立性和最后兜底保护，优先 IWDG；如果更强调任务节拍监督，希望连“喂狗过早”也能检测出来，可以使用 WWDG。有些系统会两者配合使用。

#### 易错点

- 只记住“WWDG 要喂狗”，却忽略必须在窗口内喂。
- 没有重新计算 APB1 分频变化后的 WWDG 时间参数。
- 用了 EWI 中断却没清标志，导致异常行为。
- 把 WWDG 当成 IWDG 一样随便周期刷新，结果频繁误复位。

---

### 4. 提前唤醒中断 EWI

#### 原理

当 WWDG 计数器减到 `0x40` 时，如果提前唤醒中断使能，芯片会先进入 `WWDG_IRQHandler()`。这给了程序一个“最后机会”去记录状态、保存信息或者重装计数器。

不过 EWI 的价值不只是“再喂一次狗”，更重要的是给调试和故障诊断留一个切口。

#### 特点

- 发生在真正复位之前。
- 可用于记录故障现场、打印异常标志或做一次抢救性处理。
- 常用于演示 WWDG 机制，也常用于实际产品的故障追踪。
- 若中断内不重装计数器，系统随后仍会复位。

#### 面试易问

**Q：EWI 中断的作用是什么？**

A：它让系统在 WWDG 即将导致复位前先进入一次中断，可以做日志记录、状态保存或补救喂狗，是窗口看门狗很有价值的诊断能力。

**Q：为什么有时不建议在 EWI 里无脑喂狗？**

A：因为这样可能把真正的异常掩盖掉。若系统已经失控，只靠中断反复补喂会让问题继续潜伏，工程上更合理的是记录现场后允许系统复位恢复。

#### 易错点

- 把 EWI 当成普通周期中断使用。
- 在 EWI 里无条件永久喂狗，掩盖真实异常。
- 忘记配置 NVIC，导致以为 EWI 生效其实没有进中断。
- 忘记清除 WWDG 中断标志。

---

### 5. 看门狗设计策略

#### 原理

看门狗真正难的地方不在“开没开”，而在“喂狗点放哪里”。理想的喂狗位置应该能代表系统关键任务确实完成了一轮健康执行，而不是只要 CPU 还在跑就能随便喂到。

例如在主循环结尾、关键状态机完整走通后、多个任务心跳都正常时再统一喂狗，通常比在定时中断里无脑喂狗更合理。

#### 特点

- 喂狗点应尽量代表系统关键路径健康。
- 看门狗超时时间要大于正常最坏执行时间。
- 现场系统常配合复位原因记录、错误计数和异常日志。
- 设计得好时，它能显著提高系统自恢复能力。

#### 面试易问

**Q：喂狗一般放在什么位置更合理？**

A：通常放在主循环末尾、任务调度一轮完成后，或多个关键任务都上报健康状态之后。这样只有系统关键路径都正常推进时才会喂狗，保护意义更强。

**Q：为什么不建议在高频定时中断里直接喂狗？**

A：因为即使主循环卡死，只要中断还在触发，看门狗就可能一直被喂到，失去了检测主任务失效的意义。

#### 易错点

- 喂狗点过于靠前，系统后半段异常仍然不会触发复位。
- 超时时间设置过短，偶发阻塞就被误判为异常。
- 超时时间设置过长，真实故障恢复太慢。
- 没有记录复位原因，后续排查只能靠猜。

---

## 本节核心记忆

```text
IWDG：独立于主时钟，主要防“喂狗过晚”
```

```text
WWDG：依赖 APB1 时钟，既能防“喂狗过晚”，也能防“喂狗过早”
```

```text
EWI：窗口看门狗复位前的最后一次中断机会
```

```text
喂狗位置要能代表系统真的健康运行，而不是随便找个地方反复刷新
```

## 开发过程总结

### 问题 1：程序一使能看门狗就不断复位

现象：

- 下载后程序反复重启。
- OLED 或串口只来得及显示启动信息。
- 看起来像代码没跑起来，其实是超时时间太短或根本没喂狗。

排查过程：

1. 检查预分频和重装值是否设置得过小。
2. 检查主循环是否真的执行到了喂狗函数。
3. 检查是否在调试时加入了过长延时或阻塞函数。

解决方案：

- 先用较长超时时间验证流程，再逐步压缩到目标值。
- 把喂狗点放在容易确认能执行到的位置。
- 调试阶段避免长时间停在断点上，否则看门狗也可能触发复位。

### 问题 2：窗口看门狗总是误复位

现象：

- 程序并没有卡死，但 WWDG 仍然经常复位。
- 改成 IWDG 后又表现正常。
- 说明大概率不是“喂不到”，而是“喂得不在窗口里”。

排查过程：

1. 检查 `Window` 和 `Counter` 的配置关系。
2. 检查 APB1 时钟和 WWDG 分频是否按当前主频重新计算。
3. 检查喂狗周期是否比设定窗口更早。

解决方案：

- 重新按当前 APB1 时钟计算 WWDG 时间窗口。
- 先把窗口放宽，确认机制正确后再逐步收紧。
- 用示波器、串口或 OLED 观察主循环节拍，找到合适喂狗区间。

### 问题 3：程序卡死了，但看门狗没有复位

现象：

- 主循环已经不推进。
- 系统仍然没有被看门狗拉回复位。
- 说明喂狗点设计可能存在问题。

排查过程：

1. 检查是否在定时中断里持续喂狗。
2. 检查是否有其他路径即使异常也会执行到喂狗。
3. 检查卡死位置是否发生在喂狗之后、而下一次超时又太长。

解决方案：

- 把喂狗点移动到关键任务都完成之后。
- 不要在高频中断里无脑喂狗。
- 让喂狗动作更能代表系统整体健康状态。

### 问题 4：进入 WWDG 中断后现象不符合预期

现象：

- 以为会进 `WWDG_IRQHandler()`，实际没有进。
- 或者进了中断后马上又复位。
- 有时是中断没配好，有时是没有及时清标志或重装计数器。

排查过程：

1. 检查 `WWDG_EnableIT()` 是否已调用。
2. 检查 `NVIC` 是否正确使能了 `WWDG_IRQn`。
3. 检查中断服务函数里是否清除了标志并按预期处理计数器。

解决方案：

- 确认 WWDG 外设和 NVIC 配置都完整。
- 先做最简单的“进入中断后清标志并重装计数器”实验。
- 若用于工程化诊断，再逐步加入日志、状态保存等逻辑。

## 结果展示

> 实验 1：正常运行时，主循环周期性喂 IWDG，OLED 计数持续递增，系统不复位。✅

> 实验 2：人为制造死循环后，IWDG 在超时时间到达后触发系统复位，程序重新启动。✅

> 实验 3：配置 WWDG 后，如果在合法窗口内喂狗，系统保持正常运行；若喂狗过早或过晚，则触发复位。✅

> 实验 4：使能 EWI 后，WWDG 在真正复位前可先进入一次中断，便于记录状态或做保护处理。✅

## 本节小结

本节真正值得记住的，不只是 IWDG 和 WWDG 的库函数，而是它们各自的监督思路：

```text
IWDG 更像兜底保险，强调独立可靠；
WWDG 更像节拍监督，强调“不能晚，也不能早”。
```

面试里如果被追问，看门狗最能体现项目感的回答不是“我会开”，而是你能不能讲清楚喂狗点为什么放在那里、超时时间为什么这么设、复位后怎么判断故障原因、以及为什么某些场景下要让系统复位而不是在中断里一直续命。
