# 07-2 — ADC模数转换：AD单通道与AD多通道

> 资料说明：未直接获取该视频的完整字幕与全部画面。本笔记依据可访问的分集信息、公开课程笔记、STM32F103 官方资料及前后课程上下文整理；“核心代码”属于与课程标准外设库风格一致的参考实现，并非逐字还原的视频源码。

## 实验概述

本节基于 STM32F103C8T6 的 ADC1，完成两个模数转换实验：

1. **AD 单通道**：使用电位器产生 0～3.3V 的可调模拟电压，通过 PA0 / ADC1_CH0 采集，OLED 同时显示 12 位 ADC 原始值与换算电压。
2. **AD 多通道**：使用 PA0～PA3 分别采集电位器、光敏传感器、热敏传感器和反射式红外传感器的模拟输出，并在 OLED 上显示四路转换结果。

本节的核心目标是掌握 ADC 的基本使用流程：

```text
开启 GPIO 与 ADC 时钟
        ↓
配置 ADC 时钟分频
        ↓
配置 GPIO 为模拟输入
        ↓
配置 ADC 转换模式
        ↓
使能 ADC 并完成校准
        ↓
选择规则通道并软件触发
        ↓
等待 EOC，读取转换结果
```

单通道实验固定采集一个通道；多通道实验暂不使用扫描模式，而是在每次转换前手动修改规则组第 1 个位置的通道，从而实现简单、直观的轮询采集。

## 硬件连接

### 1. AD 单通道

| 器件 | 器件引脚 | STM32 引脚 | 说明 |
|---|---|---:|---|
| 电位器 | VCC | 3.3V | 电阻固定端接模拟电源正端 |
| 电位器 | GND | GND | 另一个固定端接地 |
| 电位器 | 滑动端 | PA0 / ADC1_CH0 | 输出 0～3.3V 可调模拟电压 |
| OLED | SCL | PB8 | 软件 I²C 时钟线，按已有 OLED 工程接线 |
| OLED | SDA | PB9 | 软件 I²C 数据线，按已有 OLED 工程接线 |
| ST-Link V2 | SWDIO、SWCLK | PA13、PA14 | 程序下载与在线调试 |

### 2. AD 多通道

| 模拟信号源 | 模拟输出 | STM32 引脚 | ADC 通道 |
|---|---|---:|---:|
| 电位器 | 滑动端 | PA0 | ADC1_CH0 |
| 光敏传感器模块 | AO | PA1 | ADC1_CH1 |
| 热敏传感器模块 | AO | PA2 | ADC1_CH2 |
| 反射式红外传感器模块 | AO | PA3 | ADC1_CH3 |

> 注意：
>
> - ADC 引脚输入电压不得高于芯片的模拟电源电压 `VDDA`，本实验通常为 3.3V。
> - 传感器模块必须连接 **AO 模拟输出端**，不是只输出高低电平的 DO 数字端。
> - STM32、OLED、传感器和外部信号源必须共地。
> - 若某传感器模块使用 5V 供电，应先确认其 AO 最大输出不会超过 3.3V；必要时使用电阻分压或运算放大器调理电路。

### 2. AD.c

```c
#include "AD.h"                                                             // 引入 AD 模块头文件，获得函数声明和标准外设库定义

void AD_Init(void)                                                          // 定义 ADC1 初始化函数，统一完成时钟、GPIO、ADC 参数与校准配置
{                                                                           // 进入 AD_Init 函数体
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);                    // 开启 GPIOA 外设时钟，使 PA0～PA3 的配置寄存器能够正常工作
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_ADC1, ENABLE);                     // 开启 ADC1 外设时钟，为 ADC1 转换器提供工作时钟
    RCC_ADCCLKConfig(RCC_PCLK2_Div6);                                        // 将 PCLK2 的 72MHz 六分频为 12MHz，确保 ADC 时钟不超过允许上限

    GPIO_InitTypeDef GPIO_InitStructure;                                     // 定义 GPIO 初始化结构体，用于描述模拟输入引脚的配置参数
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AIN;                            // 将 GPIO 配置为模拟输入，关闭数字输入缓冲以降低干扰和功耗
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0 | GPIO_Pin_1 | GPIO_Pin_2 | GPIO_Pin_3; // 同时选择 PA0～PA3，供 ADC1 通道 0～3 采集模拟电压
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;                        // 为结构体速度字段赋值；模拟输入模式下该字段实际不起控制作用
    GPIO_Init(GPIOA, &GPIO_InitStructure);                                   // 将上述配置写入 GPIOA 寄存器，使 PA0～PA3 进入模拟输入状态

    ADC_InitTypeDef ADC_InitStructure;                                       // 定义 ADC 初始化结构体，用于配置 ADC1 的转换工作方式
    ADC_InitStructure.ADC_Mode = ADC_Mode_Independent;                       // 选择独立模式，使 ADC1 不与 ADC2 组成双 ADC 同步工作模式
    ADC_InitStructure.ADC_ScanConvMode = DISABLE;                            // 关闭扫描模式，每次转换只处理当前规则组位置指定的一个通道
    ADC_InitStructure.ADC_ContinuousConvMode = DISABLE;                      // 关闭连续转换，每次软件触发只执行一次转换，便于按需切换通道
    ADC_InitStructure.ADC_ExternalTrigConv = ADC_ExternalTrigConv_None;      // 不使用定时器或外部事件触发，本实验由软件命令启动规则组转换
    ADC_InitStructure.ADC_DataAlign = ADC_DataAlign_Right;                   // 选择数据右对齐，使 12 位结果位于 16 位数据寄存器的低 12 位
    ADC_InitStructure.ADC_NbrOfChannel = 1;                                  // 设置规则组序列长度为 1，因为每次只转换一个手动指定的通道
    ADC_Init(ADC1, &ADC_InitStructure);                                      // 将结构体参数写入 ADC1 控制寄存器，完成基本工作模式配置

    ADC_Cmd(ADC1, ENABLE);                                                   // 置位 ADC1 的 ADON 位，启动并使能 ADC1 外设

    ADC_ResetCalibration(ADC1);                                              // 启动 ADC1 校准寄存器复位，清除上一次可能残留的校准数据
    while (ADC_GetResetCalibrationStatus(ADC1) == SET)                       // 轮询复位校准状态，在硬件完成校准寄存器复位前保持等待
    {                                                                       // 进入复位校准等待循环
    }                                                                       // 硬件清除复位校准状态后退出等待循环

    ADC_StartCalibration(ADC1);                                              // 启动 ADC1 自校准，让硬件测量并补偿 ADC 内部偏移误差
    while (ADC_GetCalibrationStatus(ADC1) == SET)                            // 轮询校准状态，确保校准结束后再进行正式采样
    {                                                                       // 进入 ADC 校准等待循环
    }                                                                       // 硬件清除校准状态后退出等待循环
}                                                                           // 结束 AD_Init 函数

uint16_t AD_GetValue(uint8_t ADC_Channel)                                    // 定义通用采样函数，参数用于指定本次需要转换的 ADC 通道
{                                                                           // 进入 AD_GetValue 函数体
    ADC_RegularChannelConfig(ADC1, ADC_Channel, 1, ADC_SampleTime_55Cycles5); // 将目标通道写入规则组第 1 位，并选择 55.5 个 ADC 周期的采样时间
    ADC_SoftwareStartConvCmd(ADC1, ENABLE);                                  // 发送软件启动命令，触发 ADC1 规则组执行一次采样和量化转换

    while (ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET)                   // 轮询转换结束标志 EOC，等待当前通道的数字结果准备完成
    {                                                                       // 进入转换完成等待循环
    }                                                                       // EOC 置位后退出等待循环，说明数据寄存器中已有有效结果

    return ADC_GetConversionValue(ADC1);                                     // 读取 ADC1 数据寄存器并返回 0～4095 的 12 位转换结果，同时完成结果取走
}                                                                           // 结束 AD_GetValue 函数
```

### 3. main_single.c：AD 单通道

```c
#include "stm32f10x.h"                                                       // 引入 STM32F10x 芯片和标准外设库的基础定义
#include "AD.h"                                                              // 引入 ADC 初始化与通道采样函数声明
#include "OLED.h"                                                            // 引入 OLED 初始化、字符串和数字显示函数声明
#include "Delay.h"                                                           // 引入毫秒级延时函数声明，用于限制显示刷新速度

uint16_t ADValue;                                                            // 定义 16 位无符号变量，保存 ADC1_CH0 返回的 12 位原始数据
float Voltage;                                                               // 定义浮点变量，根据 ADC 原始值估算电位器滑动端电压

int main(void)                                                               // 定义程序入口函数，完成单通道 ADC 采样和 OLED 显示
{                                                                            // 进入 main 函数体
    OLED_Init();                                                             // 初始化 OLED 显示屏，为后续输出字符和数字做好准备
    AD_Init();                                                               // 初始化 PA0～PA3 和 ADC1；单通道实验实际只使用 PA0

    OLED_ShowString(1, 1, "AD:");                                            // 在 OLED 第 1 行第 1 列显示 ADC 原始值标签
    OLED_ShowString(2, 1, "Volt:0.00V");                                     // 在 OLED 第 2 行预先显示电压标签、小数点和单位

    while (1)                                                                // 进入无限循环，使单片机持续采集并刷新显示
    {                                                                        // 进入主循环体
        ADValue = AD_GetValue(ADC_Channel_0);                                // 选择 PA0 对应的 ADC1 通道 0，执行一次转换并保存原始结果
        Voltage = (float)ADValue / 4095.0f * 3.3f;                           // 按 12 位满量程 4095 和 3.3V 参考电压换算输入电压近似值

        OLED_ShowNum(1, 4, ADValue, 4);                                      // 在第 1 行显示 0000～4095 的四位 ADC 原始数据
        OLED_ShowNum(2, 6, (uint32_t)Voltage, 1);                            // 显示电压整数部分，正常输入范围内为 0～3
        OLED_ShowNum(2, 8, (uint32_t)(Voltage * 100.0f) % 100, 2);           // 提取并显示两位小数部分，使电压以 X.XXV 格式呈现

        Delay_ms(100);                                                       // 延时 100ms 后再次采样，避免 OLED 高频刷新造成视觉抖动
    }                                                                        // 结束本次主循环并立即开始下一轮采样
}                                                                            // 结束 main 函数
```

### 4. main_multi.c：AD 多通道

```c
#include "stm32f10x.h"                                                       // 引入 STM32F10x 芯片、数据类型和 ADC 通道宏定义
#include "AD.h"                                                              // 引入 ADC1 初始化和指定通道单次采样函数
#include "OLED.h"                                                            // 引入 OLED 显示函数，用于同时展示四路 ADC 数据
#include "Delay.h"                                                           // 引入毫秒延时函数，用于控制多通道数据显示刷新周期

uint16_t AD0;                                                                // 定义变量，保存 PA0 / ADC1_CH0 的电位器采样结果
uint16_t AD1;                                                                // 定义变量，保存 PA1 / ADC1_CH1 的光敏传感器采样结果
uint16_t AD2;                                                                // 定义变量，保存 PA2 / ADC1_CH2 的热敏传感器采样结果
uint16_t AD3;                                                                // 定义变量，保存 PA3 / ADC1_CH3 的反射式红外传感器采样结果

int main(void)                                                               // 定义程序入口函数，实现四个模拟输入通道的轮询采样与显示
{                                                                            // 进入 main 函数体
    OLED_Init();                                                             // 初始化 OLED 显示屏
    AD_Init();                                                               // 初始化 PA0～PA3 为模拟输入，并配置、使能和校准 ADC1

    OLED_ShowString(1, 1, "AD0:");                                           // 在第 1 行显示通道 0 的静态标签
    OLED_ShowString(2, 1, "AD1:");                                           // 在第 2 行显示通道 1 的静态标签
    OLED_ShowString(3, 1, "AD2:");                                           // 在第 3 行显示通道 2 的静态标签
    OLED_ShowString(4, 1, "AD3:");                                           // 在第 4 行显示通道 3 的静态标签

    while (1)                                                                // 进入无限循环，持续轮询采集四路模拟信号
    {                                                                        // 进入主循环体
        AD0 = AD_GetValue(ADC_Channel_0);                                    // 将规则组第 1 位切换到通道 0，触发转换并读取 PA0 的结果
        AD1 = AD_GetValue(ADC_Channel_1);                                    // 将规则组第 1 位切换到通道 1，触发转换并读取 PA1 的结果
        AD2 = AD_GetValue(ADC_Channel_2);                                    // 将规则组第 1 位切换到通道 2，触发转换并读取 PA2 的结果
        AD3 = AD_GetValue(ADC_Channel_3);                                    // 将规则组第 1 位切换到通道 3，触发转换并读取 PA3 的结果

        OLED_ShowNum(1, 5, AD0, 4);                                         // 在第 1 行显示通道 0 的 0000～4095 原始采样值
        OLED_ShowNum(2, 5, AD1, 4);                                         // 在第 2 行显示通道 1 的 0000～4095 原始采样值
        OLED_ShowNum(3, 5, AD2, 4);                                         // 在第 3 行显示通道 2 的 0000～4095 原始采样值
        OLED_ShowNum(4, 5, AD3, 4);                                         // 在第 4 行显示通道 3 的 0000～4095 原始采样值

        Delay_ms(100);                                                       // 延时 100ms 再开始下一轮四通道采集，使显示变化稳定且易于观察
    }                                                                        // 结束本轮循环并返回循环起点
}                                                                            // 结束 main 函数
```

## 关键知识点

### 1. ADC 模数转换与量化

#### 原理

ADC（Analog-to-Digital Converter）用于把连续变化的模拟电压转换为离散的数字量。

STM32F103 的 ADC 为 12 位逐次逼近型 ADC。12 位可以表示：

```text
2^12 = 4096 个离散状态
```

因此理想转换结果范围为：

```text
0 ～ 4095
```

当参考电压为 3.3V 时，理想情况下：

```text
输入 0V      → ADC ≈ 0
输入 1.65V   → ADC ≈ 2048
输入接近3.3V → ADC 接近4095
```

每一个最低有效位对应的理想电压步进约为：

```text
LSB ≈ 3.3V / 4096 ≈ 0.806mV
```

#### 特点

- 能把电位器、光照、温度、距离等模拟信号转换为程序可处理的整数。
- 分辨率越高，可区分的电压等级越多。
- ADC 数字结果与参考电压直接相关。
- 实际结果会受到量化误差、噪声、参考电压、输入阻抗和布线等因素影响。

#### 面试易问

**Q：12 位 ADC 为什么输出范围是 0～4095？**

A：12 位二进制共有 `2^12 = 4096` 种组合，从全 0 到全 1，对应十进制 0～4095。

**Q：ADC 的分辨率和精度是一回事吗？**

A：不是。分辨率表示理论上可区分的最小数字步进；精度还会受到偏移误差、增益误差、非线性、噪声和参考电压误差等影响。12 位分辨率不代表一定具有 12 位有效精度。

#### 易错点

- 把 `4095` 个最大码值误认为只有 `4095` 个量化状态。
- 只根据位数判断真实测量精度，忽略模拟电源与噪声。
- 输入电压超过 `VDDA`，可能导致结果饱和甚至损伤芯片。
- 认为 ADC 可以测量任意正负电压；普通 ADC 引脚通常只能接受规定范围内、相对模拟地的电压。

### 2. ADC 时钟、采样时间与转换时间

#### 原理

ADC 时钟来自 APB2 外设时钟 `PCLK2`，经过 ADC 专用分频器后得到 `ADCCLK`。

在常见的 72MHz 系统时钟配置下：

```text
PCLK2 = 72MHz
ADCCLK = PCLK2 / 6 = 12MHz
```

单次转换时间由采样时间和固定的 12.5 个转换周期组成：

```text
TCONV = 采样周期 + 12.5 个 ADC 时钟周期
```

本实验采用 `55.5` 周期采样时间，因此：

```text
总周期 = 55.5 + 12.5 = 68 个周期
转换时间 ≈ 68 / 12MHz ≈ 5.67μs
```

#### 特点

- ADC 时钟越高，理论转换速度越快，但不能超过芯片规定上限。
- 采样时间越长，输入采样电容越容易充到接近真实输入电压。
- 高阻抗信号源通常需要更长采样时间。
- 转换速度、输入阻抗、噪声和精度之间需要权衡。

#### 面试易问

**Q：为什么 ADC 时钟不能直接使用 72MHz？**

A：ADC 模拟电路有规定的最高工作时钟。必须通过 RCC 的 ADC 分频器降低时钟，否则转换精度和可靠性无法保证。

**Q：采样时间越短越好吗？**

A：不是。采样时间短可以提高采样率，但如果信号源阻抗较高，内部采样电容可能来不及充电，导致转换值偏低或不稳定。

#### 易错点

- 忘记配置 ADC 时钟分频，导致 ADCCLK 超限。
- 将采样时间和完整转换时间混为一谈。
- 对电位器或传感器使用过短采样时间，造成数据跳动或偏差。
- 只追求速度，不考虑前端信号源驱动能力。

---

### 3. GPIO 模拟输入模式

#### 原理

ADC 外部通道通过 GPIO 引脚接入。进行 ADC 采样时，应将对应 GPIO 配置为：

```c
GPIO_Mode_AIN
```

模拟输入模式会关闭数字输入缓冲路径，使外部电压直接进入 ADC 模拟多路选择器，减少数字输入电路带来的功耗和干扰。

本实验通道映射为：

| GPIO | ADC 通道 |
|---|---|
| PA0 | ADC1_CH0 |
| PA1 | ADC1_CH1 |
| PA2 | ADC1_CH2 |
| PA3 | ADC1_CH3 |

#### 特点

- 模拟输入模式不需要配置上拉或下拉。
- `GPIO_Speed` 字段在模拟输入模式下通常没有实际作用。
- 一个 GPIO 是否支持 ADC，需要查看对应型号的数据手册引脚定义。
- ADC 引脚不是 5V 容忍模拟输入，必须遵守模拟输入范围。

#### 面试易问

**Q：ADC 引脚为什么不能配置为普通浮空输入？**

A：普通数字输入缓冲仍会参与工作，可能增加功耗和数字噪声。模拟输入模式会关闭数字输入路径，更适合精确采集模拟电压。

**Q：所有 GPIO 都能作为 ADC 输入吗？**

A：不能。只有数据手册中标有 `ADCx_INn` 或 `ADCx_CHn` 复用功能的引脚才可接入 ADC。

#### 易错点

- GPIO 配置成上拉输入，导致测量信号被内部电阻影响。
- 使用了不具备 ADC 功能的 GPIO。
- 传感器接在 PA1，代码却读取 `ADC_Channel_0`。
- 把传感器 DO 数字输出接到 ADC 引脚，结果只能在接近 0 和满量程之间跳变。

---

### 4. 规则组、通道与 Rank

#### 原理

ADC 有多个模拟输入通道，但内部转换核心通过模拟多路选择器一次只转换一个通道。

规则组可以看成一个待转换通道列表。`ADC_RegularChannelConfig()` 的主要参数含义为：

```c
ADC_RegularChannelConfig(ADC1, ADC_Channel_2, 1, ADC_SampleTime_55Cycles5);
```

- `ADC1`：使用哪个 ADC 外设。
- `ADC_Channel_2`：选择哪个物理输入通道。
- `1`：将该通道放在规则序列的第 1 个位置，即 Rank 1。
- `ADC_SampleTime_55Cycles5`：设置该通道的采样时间。

本节始终把规则组长度设为 1，因此每次调用时只需覆盖 Rank 1 的通道配置。

#### 特点

- 通道号表示模拟输入来源。
- Rank 表示通道在规则转换序列中的顺序位置。
- 规则组最多可以按照设定顺序转换多个通道。
- 非扫描单次模式下，可在每次触发前动态修改 Rank 1，从而轮询多个通道。

#### 面试易问

**Q：ADC 通道号和 Rank 有什么区别？**

A：通道号对应具体模拟输入引脚；Rank 是该通道在规则转换序列中的位置。通道 8 可以放在 Rank 1，也可以放在 Rank 4。

**Q：为什么本节多通道采集时 `ADC_NbrOfChannel` 仍然等于 1？**

A：因为程序不是一次扫描四个通道，而是每次只把一个目标通道放入 Rank 1，完成单次转换后再切换到下一个通道。

#### 易错点

- 把 Rank 参数当成位掩码或通道号。
- 配置四个 Rank，却仍将 `ADC_NbrOfChannel` 设为 1。
- 修改通道后没有重新触发转换，读取到上一次数据。
- 不理解序列长度与扫描模式的关系。

---

### 5. 单次转换、连续转换与扫描模式

#### 原理

ADC 转换模式由两个主要选项共同决定：

```text
连续转换模式：一次触发后是否重复启动下一轮转换
扫描模式：一轮转换中是否依次处理规则组中的多个 Rank
```

本节采用：

```text
扫描模式关闭
连续模式关闭
规则组长度为 1
软件触发
```

因此，每次调用 `AD_GetValue()` 都只完成一次、一个通道的转换。

常见组合如下：

| 扫描模式 | 连续模式 | 典型行为 |
|---|---|---|
| 关闭 | 关闭 | 一次触发转换一个通道一次 |
| 关闭 | 开启 | 一个通道连续重复转换 |
| 开启 | 关闭 | 一次触发按序列扫描一轮 |
| 开启 | 开启 | 按规则序列不断循环扫描 |

#### 特点

- 单次转换结构简单，适合入门、低速采样和按需采样。
- 连续转换减少重复触发开销，适合持续采集单通道。
- 扫描模式适合自动依次转换多个通道。
- 扫描多通道时通常使用 DMA 及时搬运各通道结果。

#### 面试易问

**Q：扫描模式和连续转换模式有什么区别？**

A：扫描模式决定一轮转换是否包含多个规则通道；连续模式决定一轮完成后是否自动开始下一轮。两者控制的维度不同，可以独立组合。

**Q：单通道连续转换时需要开启扫描模式吗？**

A：不需要。只有一个通道时可关闭扫描模式，只开启连续转换即可持续采样该通道。

#### 易错点

- 认为开启连续模式就会自动采集多个通道。
- 认为开启扫描模式后结果会自动保存到多个变量。
- 模式配置与 `ADC_NbrOfChannel`、Rank 列表不匹配。
- 连续模式下忘记考虑数据读取或 DMA 搬运速度。

---

### 6. 软件触发、EOC 标志与数据读取

#### 原理

配置完成后，软件调用：

```c
ADC_SoftwareStartConvCmd(ADC1, ENABLE);
```

启动一次规则组转换。

转换结束时，ADC 将结果写入数据寄存器 `ADC_DR`，同时置位 EOC（End Of Conversion）标志。程序轮询 EOC：

```c
while (ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET);
```

EOC 置位后，通过：

```c
ADC_GetConversionValue(ADC1);
```

读取结果。

#### 特点

- 软件触发便于理解和调试。
- 轮询方式代码简单，但等待期间 CPU 无法处理其他任务。
- ADC 转换通常只需数微秒，低速应用中轮询开销可以接受。
- 高速或周期性采样更适合使用定时器触发、中断和 DMA。

#### 面试易问

**Q：为什么必须等待 EOC 后再读取 ADC 数据？**

A：EOC 表示本次转换已经完成且数据寄存器中存在有效结果。过早读取可能得到上一次转换值或未更新数据。

**Q：轮询 EOC 和 ADC 中断有什么区别？**

A：轮询会让 CPU 主动等待；中断允许 CPU 先执行其他任务，转换结束后由 ADC 事件通知 CPU，系统利用率更高。

#### 易错点

- 触发转换后立即读取数据，得到旧值。
- 永远等不到 EOC，通常是 ADC 未使能、时钟未开启或触发配置错误。
- 在高速扫描中只读取一个数据寄存器，导致前面通道的数据被后续转换覆盖。
- 阻塞式轮询大量占用 CPU，影响实时任务。

---

### 7. ADC 校准

#### 原理

ADC 内部模拟电路存在偏移误差。STM32F1 提供硬件自校准过程，在上电初始化后执行：

```text
复位校准寄存器
        ↓
等待复位完成
        ↓
启动校准
        ↓
等待校准完成
```

标准外设库对应函数为：

```c
ADC_ResetCalibration();
ADC_GetResetCalibrationStatus();
ADC_StartCalibration();
ADC_GetCalibrationStatus();
```

#### 特点

- 校准通常在每次上电后的 ADC 初始化阶段执行一次。
- 校准可减小 ADC 内部偏移误差。
- 校准必须在 ADC 已正确供电、时钟正常且外设使能后按规定流程完成。
- 校准不能消除外部参考电压误差、传感器误差和电路噪声。

#### 面试易问

**Q：ADC 校准能解决所有测量误差吗？**

A：不能。它主要补偿 ADC 内部偏移误差；外部电源、参考电压、阻抗、噪声、PCB 布局和传感器误差仍需要单独处理。

**Q：为什么要等待校准状态位清除？**

A：校准由硬件完成，需要一定时间。状态位清除表示该步骤已经结束，提前开始转换可能得到不可靠结果。

#### 易错点

- 启动校准后不等待完成就开始采样。
- 每次读取 ADC 都重新校准，造成不必要的时间开销。
- 以为校准后换算电压一定与万用表完全一致。
- ADC 时钟配置错误，使校准或转换工作异常。

---

### 8. 手动切换通道与扫描加 DMA

#### 原理

STM32F1 的多个规则通道共用一个数据寄存器。若使用扫描模式连续转换四个通道，后一个通道结果会继续写入同一个数据寄存器。

如果 CPU 没有及时搬走每个结果，前面的数据可能被覆盖。DMA 可以在每次 ADC 产生数据时自动把 `ADC_DR` 搬运到内存数组：

```text
ADC 通道序列 → ADC_DR → DMA → 内存数组
```

本节尚未进入 DMA，因此采用更直观的方式：

```text
选择通道0 → 触发 → 等待 → 读取
选择通道1 → 触发 → 等待 → 读取
选择通道2 → 触发 → 等待 → 读取
选择通道3 → 触发 → 等待 → 读取
```

#### 特点

- 手动切换通道代码容易理解，不需要 DMA。
- 每次转换都有明确的触发、等待和读取过程，不易混淆数据归属。
- CPU 需要参与每次转换，效率和最大采样率较低。
- 扫描加 DMA 更适合高速、连续和多通道同步轮询场景。

#### 面试易问

**Q：为什么 ADC 扫描多通道通常要配合 DMA？**

A：多个通道的结果依次写入同一个 ADC 数据寄存器。DMA 可以在每次结果产生后立即搬运到内存，避免 CPU 来不及读取造成数据覆盖，并降低 CPU 负担。

**Q：本节为什么不用扫描模式直接采集四个通道？**

A：为了在尚未学习 DMA 时保证数据归属清晰，本节使用单次非扫描模式，每次手动选择一个通道并立即读取结果。

#### 易错点

- 扫描四个通道后只读取一次 `ADC_DR`，误以为能得到四个结果。
- 没有 DMA 或中断搬运，导致前面通道数据被覆盖。
- 手动切换通道后忽略信号建立时间；高阻源可能需要更长采样时间。
- 将轮询采样误认为多个通道在完全同一时刻采样；实际上它们依次转换，存在时间差。

---

### 9. 数字量、电压换算与测量误差

#### 原理

理想情况下，ADC 数字量可按下式换算为输入电压：

```text
Vin ≈ ADC_Value / 4095 × VREF
```

当 `VREF = 3.3V` 时：

```c
Voltage = (float)ADValue / 4095.0f * 3.3f;
```

但开发板实际 3.3V 电源可能不是精确的 3.300V，因此高精度场景应测量实际 `VDDA`，或使用内部参考通道估算电源电压。

#### 特点

- 原始 ADC 值适合比较大小、阈值判断和相对变化。
- 电压值更直观，但依赖参考电压准确性。
- 多次平均、低通滤波和合理布线可以减小随机抖动。
- 传感器最终物理量还需根据其输出特性进行标定。

#### 面试易问

**Q：ADC 读数一直小幅跳动是否一定是程序错误？**

A：不一定。模拟噪声、参考电压波动、传感器噪声和量化误差都会造成末位抖动。可以通过平均滤波、去耦、屏蔽和改善接地减小波动。

**Q：为什么 OLED 显示 3.30V，但万用表测得 3.24V？**

A：代码使用了假定的 3.3V 参考值，而实际 VDDA 可能为 3.24V；此外 ADC 本身和万用表也存在误差。

#### 易错点

- 使用整数运算先执行 `ADValue / 4095`，导致大部分结果变成 0。
- 忘记强制转换为浮点数。
- 直接把传感器 ADC 值当成温度或距离，没有根据传感器曲线标定。
- 对波动数据只依赖软件滤波，却忽略电源去耦和模拟地布线。

## 开发过程总结

### 问题 1：ADC 数值始终为 0

#### 可能原因

- 未开启 GPIOA 或 ADC1 时钟。
- 输入引脚没有配置为模拟输入。
- 电位器滑动端未接到 PA0。
- 电位器两端没有正确连接 3.3V 和 GND。
- ADC 未使能或软件转换没有启动。
- 代码等待、读取了错误的 ADC 外设。

#### 排查方法

1. 用万用表测量 PA0 对地电压，确认旋转电位器时电压会变化。
2. 检查 `RCC_APB2Periph_ADC1` 和 `RCC_APB2Periph_GPIOA` 是否已开启。
3. 检查 PA0 是否配置为 `GPIO_Mode_AIN`。
4. 检查读取通道是否为 `ADC_Channel_0`。
5. 在调试器中观察 ADC1 的 `SR`、`CR2` 和 `DR` 寄存器。

---

### 问题 2：ADC 数值始终接近 4095

#### 可能原因

- ADC 引脚被直接接到 3.3V。
- 电位器滑动端与 3.3V 端短接。
- 传感器 AO 输出已经达到上限。
- 输入悬空并受到干扰。
- 供电或接线错误，模拟信号超过允许范围。

#### 解决方案

- 断电后重新检查电位器三个引脚。
- 用万用表确认输入没有超过 3.3V。
- 不使用的模拟输入应避免悬空。
- 检查传感器模块 AO 是否真正随环境变化。

---

### 问题 3：ADC 数值跳动明显

#### 可能原因

- 电源噪声较大。
- 模拟输入线过长或靠近 PWM、时钟等高速信号。
- 传感器输出阻抗较高，采样时间过短。
- 电位器接触不良。
- 模拟地和数字地回流路径不合理。
- OLED 刷新或其他外设造成电源扰动。

#### 解决方案

- 增大 ADC 采样时间。
- 在模拟输入端增加合适的 RC 低通滤波。
- 对多次采样结果求平均。
- 在 MCU 和传感器电源附近放置去耦电容。
- 缩短模拟信号线并保证可靠共地。
- 使用稳定的 3.3V 电源和参考电压。

---

### 问题 4：四路 ADC 数据完全相同

#### 可能原因

- 四次调用都传入了同一个 `ADC_Channel_x`。
- PA1～PA3 没有正确接入各传感器 AO。
- 传感器 AO 误接成同一根线。
- `AD_GetValue()` 没有在每次转换前调用 `ADC_RegularChannelConfig()`。
- 规则通道切换后读取的仍是旧数据。

#### 解决方案

- 逐行核对 `ADC_Channel_0`～`ADC_Channel_3`。
- 逐个断开传感器，观察对应通道是否变化。
- 使用万用表分别测量 PA0～PA3 电压。
- 确认每个通道都执行“选择、触发、等待、读取”完整流程。

---

### 问题 5：传感器变化方向与预期相反

#### 原因分析

不同传感器模块的电路连接方式不同：

- 有些光敏模块在光照增强时 AO 升高。
- 有些模块则在光照增强时 AO 降低。
- NTC 热敏电阻阻值随温度升高而降低，但分压位置不同会造成输出方向相反。
- 红外反射强度与被测物颜色、距离、角度均有关。

#### 处理方法

- 不要只凭“数值增大或减小”判断程序是否错误。
- 先测量 AO 实际电压随环境变化的方向。
- 查看模块原理图，分析分压电路。
- 在应用层按实际特性设置阈值或映射关系。

---

### 问题 6：计算出的电压与万用表差异较大

#### 可能原因

- 代码固定使用 3.3V，但实际 VDDA 并非 3.300V。
- 输入信号存在纹波或万用表响应速度不同。
- 信号源阻抗过高。
- ADC 未校准。
- 电源和参考电压去耦不足。
- 公式中发生了整数除法。

#### 解决方案

- 实测板载 3.3V，并替换代码中的参考电压。
- 确认使用 `4095.0f` 和浮点运算。
- 执行 ADC 校准。
- 增加采样时间并进行多次平均。
- 高精度应用使用更稳定的外部参考或内部参考补偿方案。

烧录多通道程序后：

- 旋转电位器时，`AD0` 明显变化。
- 改变环境光照时，`AD1` 随光敏传感器 AO 变化。
- 加热或触摸热敏传感器时，`AD2` 随温度变化。
- 改变反射物距离或颜色时，`AD3` 随红外反射强度变化。
- 四路数据按约 100ms 的周期持续刷新。

预期显示示例：

```text
AD0:2048
AD1:3150
AD2:1876
AD3:0725
```

## 本节小结

本节通过 AD 单通道与 AD 多通道实验，完成了 STM32F103 ADC 从模拟输入到数字显示的完整流程。

需要重点掌握：

1. STM32F103 ADC 为 12 位，理想输出范围为 0～4095。
2. ADC 时钟必须由 PCLK2 合理分频，不能超过器件限制。
3. 外部 ADC 引脚应配置为模拟输入模式。
4. 上电初始化后应按流程完成 ADC 校准。
5. 单次转换的基本步骤是“选通道、软件触发、等待 EOC、读取结果”。
6. 本节多通道使用单次非扫描模式，通过动态修改 Rank 1 轮询四个通道。
7. 扫描多通道时，为避免数据寄存器覆盖，通常需要 DMA 自动搬运。
8. ADC 原始值换算电压时，应考虑实际参考电压、噪声、输入阻抗和传感器标定。
